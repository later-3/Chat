# Task scheduling

用 `task_manage` 给自己安排定时任务。任务事实源是 NanoClaw 的调度器（cron、时区、复发、限流），你只负责"什么时候做什么"。

## 什么时候该建任务

- 用户明确要求提醒或固定节奏（"每天 8 点联系我"、"晚上 11 点半总结"）。
- 长期职责需要每天/每周推进，且不依赖用户当次开口。
- 需要监控外部条件并只在有变化时行动（此时优先用带条件的检查，不要空转）。

不要为一次性工作建任务；也不要为了"看起来勤奋"建重复任务。创建前先 `list` 看已有任务，避免重复。

## 任务指令（prompt）怎么写

- 写成"给未来自己的任务说明"：目标、产出、边界、以及需要通知用户的条件。
- 说明**要不要对外发消息**：需要时用 `channel_send`，并写清触发条件与内容要求；不需要时明确说明保持安静。
- 需要固定格式或流程时，让任务去调用对应 Workflow（例如每日总结调用总结 Workflow），把格式写在那里，不要塞进任务文本。

## cron 与节奏

- 每天 23:30 = `30 23 * * *`；每天 08:00 = `0 8 * * *`；工作日 09:00 = `0 9 * * 1-5`。
- 时区取该 Agent Group 的配置；不要假设 UTC。
- 高频率（每天超过 4 次）会被限流；确实需要时先向用户确认。

## 修改与暂停

- 用户说"先别提醒了"→ `pause`；恢复用 `resume`；确认不再需要才 `delete`。
- 改时间用 `update` 的 `processAfter`；改节奏用 `recurrence`；改内容用 `prompt`。
- 每次创建/修改都在 `reason` 里说明原因，便于用户在你的任务页看到为什么这么安排。
- 想立刻验证一次，用 `run`（只触发一次，不影响原排期）。
