## BP-27：App.submit（浏览器入口）

**文件**：[frontend/src/App.tsx:407](../../frontend/src/App.tsx#L407)

停住后看 5 个变量：

| `selectedWorkflow` | `"continuous-chat"`                                   | 前端状态 |
| `status`           | `"idle"`                                              | 前端状态 |
| `messages`         | `[{ role: "user", ... }]`                             | 前端状态 |

**这 5 个变量是什么**：

- **`draft`**：输入框里当前正在打的文字（"草稿"）。[App.tsx:66](../../frontend/src/App.tsx#L66) `const [draft, setDraft] = useState("")` 定义。用户每敲一个键 `onChange` 更新它，点发送时读出来用。C++ 类比：`std::string input_buffer`，用户打字时实时更新，发送时取值。注意：`draft` 只是前端内存里的临时草稿，**不是 Product Store 权威消息**。只有发送到后端、`prepare_agui_run` 写进 `MessageRecord` 表后才成为权威事实。刷新页面会丢失（Chat 用 `localStorage` 做了 draft 持久化兜底，但仍是前端存储）。

- **`activeSession`**：当前选中的会话对象。包含 `id`（会话ID，对应后端的 `threadId`）、标题、状态等。用户在左侧会话列表点哪个会话，`activeSession` 就是哪个。C++ 类比：`struct Session { string id; string title; ... }; Session* active;`。

- **`selectedWorkflow`**：用户选的 Workflow 类型（`"continuous-chat"` 是默认的持续协作主 Workflow）。决定后端跑哪个 39 节点 Workflow。C++ 类比：`enum WorkflowType { CONTINUOUS_CHAT, ... }; WorkflowType current;`。

- **`status`**：当前 Run 的运行状态。`"idle"` = 空闲，可以发新消息；`"running"` = Agent 正在跑，不能再发。C++ 类比：`enum Status { IDLE, RUNNING, ERROR };`。点发送前必须检查 `status === "idle"`，否则 `submit()` 直接 return。

- **`messages`**：当前会话的消息列表（React state）。每条消息有 `role`（`"user"` / `"assistant"`）和 `content`。这是前端的**投影**，不是 Product Store 权威事实--后端才是真正的消息主人。

这层只做一件事：把 UI 状态收集起来，传给 `useChatAgent.send()`。**不碰网络、不碰数据库**。

**真实源码**（[App.tsx:398-422](../../frontend/src/App.tsx#L398)）：

**这 4 个变量是什么**：

- **`content`**：从 `draft` 复制过来的用户文字。[App.tsx:410](../../frontend/src/App.tsx#L410) `const text = draft; setDraft("");` --先把 draft 复制到 text，再清空 draft（清空输入框）。

- **`HttpAgent`**：`@ag-ui/client` 框架提供的 HTTP 客户端类。构造时传入 `url`（后端地址）和 `fetch`（HTTP 请求函数），调 `runAgent(input)` 就发 POST 并返回 SSE 流。C++ 类比：`class HttpClient { HttpClient(string url); void post(Request req); }`。

## 4.1 校验链（5 道门，任一失败都不写库）

```python
# 第 1 道：必填校验

agui_run_id = str(input_data.get("run_id") or input_data.get("runId") or "")

    raise ProductSessionError("AG-UI请求必须包含threadId和runId")
# -> session_id = "5ca4de42-7aa2-4e6c-b621-2c25b0fcca54", agui_run_id = "runtime-run" ✓

# 第 2 道：resume 分流（本次不是 resume，跳过）
if input_data.get("resume") is not None:
    ...

# 第 3 道：打开事务，查会话状态
async with self.database.sessions.begin() as transaction:
    session = await self._session(transaction, session_id)
    if session.status != "active":
        raise ProductSessionConflict("已归档会话不能启动新Run")
    # → session.status = "active" ✓

    # 第 4 道：幂等检查（相同 runId 是否已存在）
    existing_protocol = await transaction.scalar(

            RunProtocolRecord.session_id == session_id,
            RunProtocolRecord.agui_run_id == agui_run_id,

    if session.active_run_id is not None:
        raise SessionBusy("该会话已有活动Run")
    # → session.active_run_id = None ✓

    # 第 6 道：客户端历史前缀 + 恰好 1 条新 User 消息
    persisted = ...  # 查 Product Store 里已 committed 的消息
    if len(incoming) != len(persisted) + 1:
        raise SessionHistoryConflict("客户端必须携带服务端历史前缀和恰好1条新User消息")
    # → incoming 有 1 条，persisted 有 0 条（第一次对话）✓
```

## 4.4 第 2 次命中（Worker 复核）

同一个 `prepare_agui_run` 会在 Worker 跑 `ProductAwareWorkflow.run` 时**第 2 次被调**。这次走的是第 4 道幂等检查的另一个分支：

```python
existing_protocol = await transaction.scalar(...)  # → 找到了！
if existing_protocol is not None:
    run = await transaction.get(RunRecord, existing_protocol.product_run_id)
    # -> run.id = "61956a4d-4875-4977-b4a8-b82b2386f22d"
    # 校验客户端 messages 和已存的 Product Message 是否一致
    if 内容漂移:
        raise IdempotencyConflict("相同AG-UI runId携带了不同请求内容")

    return AcceptedRun(product_run_id=run.id, ...)
```

## 内部代码展开（简化示意）

真实源码在 [service.py:100-193](../../backend/app/runtime_execution/service.py#L100)，约 93 行，包含 resume 分支和幂等检查。以下是**简化示意**（保留关键逻辑，省略 resume 和幂等细节）：

```python
async def enqueue(self, *, accepted, endpoint_key, ...) -> EnqueuedRuntime:
    async with self.database.sessions.begin() as transaction:
        # 1. 查最近一条 RunAttempt（刚被 prepare_agui_run 创建的）
        attempt = await transaction.scalar(
            select(RunAttemptRecord)
            .where(RunAttemptRecord.run_id == accepted.product_run_id)
            .order_by(RunAttemptRecord.attempt_number.desc())
            .limit(1)
        )
        # -> attempt.id = "20ecd9d5-2a52-4ac5-b950-605dcd7d3e74"

        # 2. 查是否已有对应 RuntimeJob
        job = await transaction.scalar(
            select(RuntimeJobRecord).where(RuntimeJobRecord.run_attempt_id == attempt.id)
        )
        # → job = None（第一次，没有）

        # 3. 创建 RuntimeJobRecord
        if job is None:
            job = RuntimeJobRecord(
                id="e0384058-00e3-4fe3-be6a-111112bc2d29",           # ← 后面要用
                product_run_id="61956a4d-4875-4977-b4a8-b82b2386f22d", # ← 关联 Product Store 的 Run
                run_attempt_id="20ecd9d5-2a52-4ac5-b950-605dcd7d3e74",
                endpoint_key="test",
                workflow_definition_id="test-workflow",
                workflow_version="1.0.0",
                status="queued",                  # 初始状态：排队中
                recoverability="safe_requeue",     # 崩溃可安全重领
                input_payload_json={"threadId": "...", "messages": [...]},
                input_hash=_hash(input_data),     # 输入指纹
                available_at=utc_now(),
            )
            transaction.add(job)
            attempt.status = "accepted"          # Attempt 状态推进
            start_sequence = 0
```

> 说明：真实源码还有 `elif accepted.is_resume:`（恢复分支）和 `else:`（幂等冲突检查），约 40 行。测试场景不走 resume，所以这里省略。


```python
async def event_stream() -> AsyncGenerator[bytes]:
    sequence = enqueued.start_sequence          # ← start_sequence = 0
    idle_cycles = 0
    while True:
        events, job = await runtime.events_after(
            job_id=enqueued.job_id,              # ← "e0384058-00e3-4fe3-be6a-111112bc2d29"
            after_sequence=sequence,
        )
        if not events:
            # 没有新事件
            if job["status"] in {"failed", "cancelled", "outcome_unknown"}:
                # Worker 失败也要给浏览器一个终态帧
                yield _sse({
                    "type": "RUN_ERROR",
                    "message": job.get("failure_summary") or "Execution Worker未能完成本次Run。",
                    "code": job.get("failure_code") or "EXECUTION_WORKER_FAILED",
                })
                return
            idle_cycles += 1
            if idle_cycles % 150 == 0:
                yield b": runtime-keepalive\n\n"   # ← 每 150 次空闲发一次心跳
            await asyncio.sleep(poll_interval_seconds)   # ← 0.08 秒后再查
            continue
        idle_cycles = 0
        for event in events:
            sequence = int(event["sequence"])
            payload = dict(event["payload"])
            yield _sse(payload, sequence=sequence)       # ← 推给浏览器
            # ← 第一次：sequence=1, type="RUN_STARTED"
            # ← 第二次：sequence=2, type="TEXT_MESSAGE_START"
            # ← 第三次：sequence=3, type="TEXT_MESSAGE_CONTENT"
            # ← 第四次：sequence=4, type="TEXT_MESSAGE_END"
            # ← 第五次：sequence=5, type="RUN_FINISHED"
            if payload.get("type") in {"RUN_FINISHED", "RUN_ERROR"}:
                return   # 终态帧后关闭流
```

```python
async def claim_one(self, *, worker_id, lease_seconds):
    now = utc_now()
    lease_until = now + timedelta(seconds=6)
    async with self.database.sessions.begin() as transaction:
        # 找一个 queued 状态的 Job
        candidate = await transaction.scalar(
            select(RuntimeJobRecord)
            .where(RuntimeJobRecord.status == "queued",
                   RuntimeJobRecord.available_at <= now)
            .order_by(RuntimeJobRecord.available_at, ...)
            .limit(1)
        )
        # -> candidate.id = "e0384058-00e3-4fe3-be6a-111112bc2d29"（找到我们入队的那个）

        # 原子地改成 leased，写上 worker_id 和租约过期时间
        claimed = await transaction.execute(
            update(RuntimeJobRecord)
            .where(RuntimeJobRecord.id == candidate.id,
                   RuntimeJobRecord.status == "queued")  # CAS 条件
            .values(
                status="leased",
                lease_owner=worker_id,
                lease_epoch=candidate.lease_epoch + 1,   # Epoch 递增
                lease_expires_at=lease_until,             # 6 秒后过期
            )
        )
        # 如果 affected_row_count != 1，说明被别的 Worker 抢了
```

```python
async def _execute_claim(self, claim):
    breakpoint()  # BP-03 停在这
    # ← 此时 claim = ClaimedRuntime(job_id="e0384058-...", product_run_id="61956a4d-...", ...)

    heartbeat_task: asyncio.Task[None] | None = None
    terminal_seen = False
    last_control_check = 0.0
    try:
        # 1. 按 endpoint_key 找 Runner（组合根注册的自研 ProductAwareWorkflow）
        runner = self.registry.require(claim.endpoint_key)
        # ← claim.endpoint_key = "test"（测试用）

        # 2. 把 Job 状态从 leased 改成 running，续租
        await self.runtime.start(claim, worker_id=self.worker_id, lease_seconds=self.lease_seconds)

        # 3. 启动心跳协程（每 10 秒续租一次，防止 Lease 过期）
        heartbeat_task = asyncio.create_task(
            self._heartbeat_loop(claim),
            name=f"runtime-heartbeat-{claim.job_id}",
        )

        # 4. 跑 Runner，逐个拿事件
        async for event in runner.run(claim.input_data):
            payload = self._public_payload(event)
            event_type = str(payload.get("type") or "")
            # ← 第一次循环：event_type = "RUN_STARTED"
            # ← 第二次：event_type = "TEXT_MESSAGE_START"
            # ← 第三次：event_type = "TEXT_MESSAGE_CONTENT"
            # ← 第四次：event_type = "TEXT_MESSAGE_END"
            # ← 第五次：event_type = "RUN_FINISHED"

            # 5. 检查取消命令（每 0.1 秒查一次）
            monotonic_now = time.monotonic()
            if monotonic_now - last_control_check >= 0.1 or event_type in {"RUN_FINISHED", "RUN_ERROR"}:
                last_control_check = monotonic_now
                cancel_command_id = await self.runtime.pending_cancel_command(claim)
                if cancel_command_id is not None:
                    await self.runtime.append_terminal_and_settle(...)  # 写终态
                    terminal_seen = True
                    return

            # 6. 分类处理事件
            if event_type == "RUN_STARTED":
                await self.runtime.mark_external_dispatch(claim, worker_id=self.worker_id)
                # ← Job.external_dispatch_state 从 "not_started" 变成 "dispatching"

            interrupt = event_type == "RUN_FINISHED" and self._is_interrupt(payload)
            is_terminal = event_type == "RUN_ERROR" or (event_type == "RUN_FINISHED" and not interrupt)

            product_terminal_status: str | None = None
            if is_terminal and event_type == "RUN_FINISHED":
                product_terminal_status = await self._require_product_terminal(claim)
                # ← 真正终态前先过 Product 提交门

            if event_type == "RUN_ERROR":
                terminal_seen = True
                await self.runtime.append_terminal_and_settle(
                    claim, worker_id=self.worker_id, payload=payload,
                    status="failed", is_terminal=True,
                    failure_code=str(payload.get("code") or "runtime_run_error")[:100],
                    failure_summary=str(payload.get("message") or "MAF Run失败")[:500],
                )
            elif event_type == "RUN_FINISHED":
                terminal_seen = True
                await self.runtime.append_terminal_and_settle(
                    claim, worker_id=self.worker_id, payload=payload,
                    status=(
                        "waiting_human" if interrupt
                        else "cancelled" if product_terminal_status == "abandoned"
                        else "succeeded"
                    ),
                    is_terminal=not interrupt,
                )
            else:
                # 普通事件（TEXT_MESSAGE_START、TEXT_MESSAGE_CONTENT、TEXT_MESSAGE_END 等）
                await self.runtime.append_event(
                    claim, worker_id=self.worker_id, payload=payload, is_terminal=False,
                )
                # ← 写进 Journal，sequence 从 1 递增到 4

        if not terminal_seen:
            raise RuntimeError("MAF Runtime没有产生RUN_FINISHED或RUN_ERROR")
    except RuntimeLeaseLost:
        logger.warning("execution_worker_lease_lost ...")
    except asyncio.CancelledError:
        # Lease 过期，Reconciler 兜底
        ...
```

## append_event 内部：写 Journal

**文件**：[service.py:289](../../backend/app/runtime_execution/service.py#L289)

```python
async def append_event(
    self,
    claim: ClaimedRuntime,
    *,
    worker_id: str,
    payload: dict[str, Any],
    is_terminal: bool,
) -> dict[str, Any]:
    encoded = _canonical(payload)
    payload_hash = hashlib.sha256(encoded).hexdigest()
    event_type = str(payload.get("type") or "UNKNOWN")
    async with self.database.sessions.begin() as transaction:
        # CAS：只有持有当前 Lease Epoch 的 Worker 才能写
        sequence = await transaction.scalar(
            update(RuntimeJobRecord)
            .where(
                RuntimeJobRecord.id == claim.job_id,
                RuntimeJobRecord.run_attempt_id == claim.run_attempt_id,
                RuntimeJobRecord.lease_owner == worker_id,        # ← 必须是当前 Worker
                RuntimeJobRecord.lease_epoch == claim.lease_epoch,  # ← 必须是当前 Epoch
                RuntimeJobRecord.status.in_({"leased", "running"}),
            )
            .values(
                last_event_sequence=RuntimeJobRecord.last_event_sequence + 1,
                updated_at=utc_now(),
            )
            .returning(RuntimeJobRecord.last_event_sequence)
        )
        if sequence is None:
            raise RuntimeLeaseLost("旧Worker不能写入Runtime Event")
        # ← 如果 sequence = None，说明 Lease 被别人抢了或状态不对

        # 插入事件记录
        record = RuntimeEventRecord(
            id=_uuid(),
            runtime_job_id=claim.job_id,
            run_attempt_id=claim.run_attempt_id,
            sequence=int(sequence),                # ← 递增序号：1, 2, 3, 4, 5
            agui_event_type=event_type,            # ← "RUN_STARTED"/"TEXT_MESSAGE_START"/...
            public_payload_json=payload,           # ← 完整事件 JSON
            payload_hash=payload_hash,             # ← SHA256 指纹
            is_terminal=is_terminal,               # ← 只有 RUN_FINISHED 是 True
            size_bytes=len(encoded),
        )
        transaction.add(record)
    return self._event_view(record)
```

**数据流变化**：

```
Worker yield 一个事件 {type: "TEXT_MESSAGE_CONTENT", messageId: "assistant-runtime", delta: "已恢复"}
-> append_event 写 RuntimeEventRecord(sequence=3, payload={...})
-> RuntimeJobRecord.last_event_sequence 从 2 变成 3
-> 事务提交
-> event_stream 协程的 events_after(after_sequence=2) 查到这条
-> yield _sse(payload) 推给浏览器
```

| 概念 | 是什么 | C++ 类比 |

| `lease_expires_at` | 租约过期时间（now + 30s），过期后别的 Worker 可重领 | `timestamp deadline` |
| `lease_owner` | 当前持有租约的 Worker ID | `string workerId` |
| `heartbeat` | 心跳，Worker 每 10 秒续租一次，防止 Lease 过期 | `ping()` |
