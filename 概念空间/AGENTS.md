# Chat 概念资产目录规则

## 1. 本目录负责什么

本目录维护 Chat 产品在长期协作中需要统一理解的概念名称、边界、关系、别名和反例。根目录的[概念空间方法来源](../概念空间.md)解释方法；[概念资产索引](./00-索引.md)负责发现；具体概念簇负责唯一语义正文。

本目录不拥有产品定位、项目进度、字段级 Schema、源码行为或框架版本事实。出现冲突时按以下顺序处理：

1. 用户最新且明确的审核决定。
2. 根[协作规则](../AGENTS.md)与[项目上下文](../PROJECT_CONTEXT.md)中的稳定产品事实。
3. [项目状态](../PROJECT_STATE.md)中的当前实现事实。
4. 匹配版本的源码、合同测试和运行证据。
5. 本目录对这些事实的概念化整理。

如果概念正文与更高层事实冲突，必须把概念标为“修订中”并修正文身，不能用概念文件反向覆盖事实源。

## 2. 信息怎样分层

```text
概念空间.md                    方法来源：概念空间是什么、为什么需要
概念空间/00-索引.md            全局发现：作用域、概念簇、状态和唯一正文
概念空间/Chat/00-索引.md       Chat作用域阅读路线
概念空间/Chat/<概念簇>.md      多个强关联概念的唯一语义边界
PROJECT_CONTEXT.md             稳定产品定义和核心对象责任
PROJECT_STATE.md               当前实现、验证、缺口和风险
源码、测试、协议规范           具体行为与技术事实
```

1. 索引只导航，不复制完整定义。
2. 同一概念只有一份概念正文；其他文档链接它。
3. 概念簇可以包含强关联的子概念，避免每个名词单独建档。
4. 代码类名、网络DTO和数据库表可以映射到概念，但不能自动定义产品概念。
5. 临时表达就地解释；没有长期价值时不进入本目录。

## 3. 什么时候新增或拆分概念

满足下列任一条件且已有真实使用场景时，才进入概念资产：

1. 曾发生实质性人机理解偏差。
2. 会影响用户选择、审批、权限、状态或恢复动作。
3. 被多个页面、模块、协议或文档反复引用。
4. 同一个词在产品层、协议层和运行时层有不同含义。
5. 需要独立修订、改名、停用或替代。

子概念默认保留在所属概念簇；只有能够独立使用、持续膨胀或需要独立生命周期时才拆文件。禁止为尚未出现的概念预建空目录。

## 4. 最低语义合同

每份长期概念正文必须让读者找到：

1. 文档治理信息、概念状态和实现状态。
2. 一句话理解和正式定义。
3. 为什么需要，以及它解决的真实交互问题。
4. 包含什么、不包含什么。
5. 上下游和相邻概念关系。
6. 人、AI、界面、API和代码应怎样使用名称。
7. 正例与反例。
8. 当前已实现、尚未实现和未知内容。
9. 事实来源、维护触发和验证方式。

概念状态与实现状态必须分开：一个概念可以已经有效，但对应能力仍未实现；一段代码已经存在，也不代表它采用的名称已经成为有效产品概念。

## 5. 生命周期

| 概念状态 | 含义 | 允许使用方式 |
|---|---|---|
| 候选 | 定义已经形成，但用户或事实证据尚不足 | 可以讨论，不能作为稳定前提强制下游采用 |
| 有效 | 边界已确认，并被产品、设计或实现正式使用 | 可以引用，仍可被新事实修订 |
| 修订中 | 已发现冲突、歧义或环境变化 | 引用时必须提示争议和待决内容 |
| 已停用 | 不再用于新工作 | 保留原因、旧称和替代入口 |

实现状态统一使用“未实现、局部实现、已实现、已验证”及必要说明。`PROJECT_STATE.md`是实现状态的最终事实源，概念正文只做带链接的摘要。

## 6. 人、AI和产品怎样使用

1. AI在任务开始时先识别高冲突词，只按需读取相关概念簇，不通读全部资产。
2. 面向用户第一次实质使用重要概念时，必须就地用普通语言解释，不能只丢链接。
3. `Session`、`Run`、`Workflow`、`Attempt`、`Context`、`Tool`、`Approval`和`Canvas`在可能歧义时必须带限定词。
4. 用户动作使用“动作 + 对象 + 后果”，例如“放弃本次模型调用并返回输入框”，避免只写“确认”“重来”“继续”。
5. UI、API和代码中的ID必须带对象范围；`threadId`、外部会话ID或模型Session ID不能冒充授权。
6. AI提出新概念时先标为候选，说明必要性、边界和与现有概念的差异；用户确认后才进入有效状态。

## 7. 修改、改名和停用

1. 在概念唯一正文中修改定义，再同步两个索引的名称、状态和入口。
2. 改名时保留旧称为别名；停用时保留历史原因并链接替代概念。
3. 修改产品责任时同时按根治理规则更新`PROJECT_CONTEXT.md`；修改实现事实时更新`PROJECT_STATE.md`。
4. 概念正文不得复制密钥、私有配置、用户会话内容或隐藏推理。
5. 概念解释不能把MAF、AG-UI或Provider协议事实写成本项目原生保证；必须标明来源层级。

## 8. 验证

修改概念资产后至少运行：

```bash
uv run python 概念空间/验证概念空间.py
git diff --check
```

结构校验只能证明必要语义、索引和链接存在。概念真正有效还要通过：

1. 新用户或新AI能否解释“它是什么、它不是什么”。
2. 能否指出对象所有者、生命周期和用户可执行动作。
3. 同一用户动作在UI文案、API、状态机和Trace中是否使用同一语义。
4. 失败、拒绝、修改、重试和恢复场景是否仍不会把相邻概念混用。
