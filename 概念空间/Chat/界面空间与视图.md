## 一句话理解

**Workspace是整体工作区；Activity Rail负责全局切换；连续Chat Pane承载协作；Workbench是右侧容器；Workflow Run View是其中一个运行投影；Canvas是未来独立、可保存和编辑的空间型Artifact。**

## 为什么需要

用户用“ChatGPT Canvas模式”说明左右布局时，如果系统直接把右侧区域命名为Canvas，就会把布局容器、Workflow状态、审批编辑器和未来白板内容混在一个状态对象里，导致持久化、关闭、恢复和权限都无法定义。

## 定义与边界

| 概念 | 定义 | 不是什么 |
|---|---|---|
| Workspace / 工作区 | Chat页面内承载会话导航、对话、Workbench和全局交互的整体布局 | 不是某个业务对象或数据库事实 |
| Activity Rail / 活动栏 | 左侧窄栏，用于切换主页、连续对话、协作日历、灵感花园和其他一级工作空间 | 不是Session列表、业务事实源或项目树 |
| Session Sidebar / 会话侧栏 | 当前实现中用于创建/切换Product Session的可折叠导航；目标信息架构中不再作为默认用户入口 | 不是Conversation History，也不能决定模型Context |
| Chat Pane / 对话窗格 | 展示连续对话流、当前状态和输入框的主要交互区域 | 不是整个Workspace，也不拥有权威消息或无限模型上下文 |
| Workbench / 右侧工作区 | 与Chat Pane平行、可伸缩并承载不同功能视图的通用容器 | 不是Canvas、Workflow或Artifact本身 |
| Workflow Run View / 工作流运行视图 | Workbench中投影某个Product Run实际Workflow节点、状态、审批和公开内容的视图 | 不是Workflow选择器、Definition编辑器或运行事实源 |
| Canvas / 画布 | 拥有稳定ID、版本、内容、权限和持久生命周期的空间型Artifact | 不是左右分栏布局、Workbench或Workflow Trace |
| Artifact Preview / 产物预览 | Workbench中只读或受控查看某个Artifact的视图 | 不是Artifact本身 |
| Evidence View / 证据视图 | 查看来源、有效性和结果依据的投影 | 不是Trace或隐藏推理 |
| Configuration Center / 配置中心 | 从顶部统一打开并管理Session、Agent、Tool、Provider等配置的界面容器 | 保存配置不等于启动执行或授予权限 |
| UI Projection / 前端投影 | REST、AG-UI或本地页面状态组合出的可视模型 | 不是Product DB或运行终态权威来源 |

## 概念关系

```text
Workspace
├── Activity Rail（主页、对话、日历、灵感）
├── Chat Pane（连续对话与输入）
└── Workbench（与Chat Pane平行）
    ├── Workflow Run View
    ├── Canvas View -> Canvas Artifact
    ├── Artifact Preview -> Artifact
    └── Evidence View -> Evidence

顶部入口 -> Configuration Center
```

Workbench的开合、宽度和当前Tab是页面状态；Canvas内容、Artifact和Workflow Run终态分别由自己的事实源拥有。

## 人和系统怎样使用

1. 用户打开Chat默认进入个人主页，通过Activity Rail进入连续对话、协作日历和灵感花园。
2. 用户发送前在Chat Pane选择Workflow；发送后Workbench切换或打开对应Workflow Run View。
3. Workflow完成后，运行状态进入Product Trace；只有明确创建的内容才成为Artifact或Canvas。
4. 配置中心保存Agent/Tool/Session设置，但不自动创建Run或执行Tool。
5. UI文案和组件名使用业务对象名；“Panel”“View”“Pane”表示投影或容器，不能被当成领域对象。
6. Product Session仍由服务端管理恢复和权限；移除默认Session Sidebar不等于删除Product Session。

## 正例与反例

正例：左侧Chat持续对话，右侧Workflow Run View实时显示节点；关闭Workbench不会取消Run。

反例：把右侧所有内容存在`canvasState`，其中同时包含Workflow节点、审批、白板便签和布局宽度。

反例：Workflow结束后自动把Trace写进Canvas，用户没有创建或批准该Artifact。

反例：用户保存Agent配置后，页面立即显示Workflow正在运行。

## 当前状态与未知

当前会话列表与聊天区域独立滚动；桌面Session Sidebar可向左完全折叠，窄屏通过菜单和遮罩以抽屉方式展开/收起。目标信息架构已经确认改为Activity Rail、个人主页、连续对话流和协作日历，但尚未实现。Chat Pane与Workbench平行，Workbench可切换Workflow运行视图、Project Explorer、Work Board、Knowledge和Context Inspector；关闭视图不会取消Product Run。未来持久Canvas仍需作为独立Artifact设计与实现，不能把现有Workbench页面状态冒充Canvas事实。
