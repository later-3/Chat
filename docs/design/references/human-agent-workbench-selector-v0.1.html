Chat 工作台组合选型板 v0.1

一句话：用既有 9 项研究的真实画面，在同一页组合出 Chat 自己的工作台骨架——先选页面中心（A），再定 Agent 是谁（B），最后走一遍从目标到交付的生命周期（C）。本页不排名参考产品，只做组合选型；所有截图均为已登记证据，命题与边界以研究文件为准。

A · Workbench Surface页面中心由谁拥有：对话、工作对象、执行现场、监督队列……同一时刻只有一个主中心，可再加最多 2 个辅助表面。
B · Agent ConstitutionAgent 是谁、能做什么、记得什么、边界在哪里：Identity / Capability / Memory / Permission 四项逐项选参考方向。
C · Workflow Lifecycle怎样从目标走到交付与继续：12 个阶段折为 Phase 1–4，逐阶段选参考方向或标为 Chat 自建。

建议主路径：理解三轴 → 在 A 轴选唯一页面中心 → 补 B 轴四项 Constitution → 按 Phase 走完 C 轴 12 阶段 → 在“组合汇总”查看当前组合与共同缺口。

F 已批准合同 / 冻结事实 / 已批准研究登记 O 已检查产品 UI 画面直接可见 I 跨证据归纳或 Chat 适配判断 U 当前没有证明

A 轴 · Workbench Surfaces（8 类）

用 radio 选唯一页面主中心；用 checkbox 选辅助表面（最多 2 个）。默认推荐：主中心 A2，辅助 A3 + A5。

A1 · Project / Work / Task Board

页面中心所有者：Work-object（长期工作对象及其状态）

状态：未选

主参考：
Plane（Work-object-owned + 多布局 + Intake）
补充参考：
Basecamp（Room-owned）、Linear（Work-list-owned + Peek）
  • 可直接借：5 种布局切换 + 身份/筛选连续；Basecamp 四层作用域；Linear List/Peek/Detail 三档阅读。
  • 必须适配：Chat 的 Work 不等于 Issue；Intake Accept/Decline 不等于完整 HITL。
  • 拒绝照搬：不复制多套事实；不把六宫格当全局骨架。

证据边界：F · audit + O · 冻结原型画面。截图只证明布局结构存在，不冒充完整交互路径。

A8 选择

B 轴 · Agent Constitution（4 类）

四项都必须明确选择；选“Chat 自建”等于该维度当前没有参考方向。推荐：B1 Agent Feed · B2 AnythingLLM · B3 AnythingLLM + Heptabase · B4 Agent Feed。

显式缺口（U）：9 项研究中没有任何一个提供完整耐久 Agent Profile（身份 + 职责 + 能力 + 记忆 + 权限 + 当前工作 + 贡献历史）。无论 B 轴怎样组合，Agent Profile 都必须由 Chat 自建。另：AnythingLLM 的 provider/model 配置属于 B2 Capability，不属于 B1 Identity。

B1 · Identity / Role / Owner / Participant

状态：未选

主参考：
MS Agent Feed（Agent 身份类型化 + delegation 明示 participant visibility）
补充参考：
AnythingLLM Workspace Agent 模型选择仅属 B2，不作 B1 证据
  • 可直接借：Agent 身份类型化；delegation 明示 participant visibility；Agent 有独立终态。

B4 参考方向

C 轴 · Agent Workflow Lifecycle（12 阶段 / Phase 1–4）

逐阶段选择参考方向；未选参考即显示“Chat 自建”。折叠展开不影响选择状态。

四个概念必须分开：Agent Constitution（B 轴：谁）≠ Agent Workflow Definition（定义/配置/版本/发布/触发）≠ Agent Workflow Run（一次执行的进度/介入/结果）≠ Business / Project Workflow（业务 Work item 状态流，不得冒充 Agent Workflow，F）。

本轴证据边界：AnythingLLM Stop 只证明 cancel/abort，不证明 Pause/Resume（O · ACW-12）；AnythingLLM 的 Thinking 只是源 UI 标签，不是 Chat 应保存的隐藏推理（F · AGENTS.md §6.6）；Scheduled Jobs 只证明 Trigger → Run → History 可见路径，不是完整 Workflow 生命周期；version/publish、真正 Pause/Resume、完整 Agent Profile 均为 U 缺口。
