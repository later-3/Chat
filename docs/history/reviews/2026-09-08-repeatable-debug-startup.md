# 新环境初始化与重复调试启动

场景：Agent按文档搭建新环境，用户随后反复执行启动脚本或F5；正常Chat不受影响，数据不重新初始化。

范围：扩展现有调试启动器，增加前台组合启动/停止和本机Lab初始化。`.data/debug`下的角色归属记录包含PID、OS启动时间、用户、进程组和随机标识；同角色控制串行，旧owner优先正常退出，再对已确认属于自己的残留进程组TERM/KILL。PID复用、未知占用、无法确认leader的孤儿或损坏记录均不扩大杀进程范围。生产继续使用原生服务管理器，尚未实施跨服务业务排空。

初始化使用操作者ncl创建/复用Group和CLI Wiring，使用窄Gateway读取Profile并补齐Memory，仅缺少时写调试Registry。Backend不依赖ncl或Nano数据库；不新增Agent Runtime，不修改子模块，不加载真实Bot或生产凭据。生产实体/Registry仍由部署Agent按实际身份配置，文档列出交付检查，不能把debug样例当作生产默认Agent。

验证：隔离`pnpm verify`通过379条测试（工具13、Backend225、Frontend112、built28、dev1），类型及生产构建通过；最后补强过期control锁的并发回收后，完整工具13条再次通过。包含角色重复启动、SIGKILL后的孤儿回收、SIGSTOP暂停owner的有界强制替换、无关监听器保留、PID复用、并发控制、部分初始化重试。首次暂停测试等待预算小于允许的退出/强制清理总期限，按操作上限修正等待后通过，未减少断言。

真实调试栈完成多次启动/替换/停止，6个私有配置与Memory文件哈希不变；重启后的Web文本、read Skill、Session重读、Web长期同事和Nano CLI回复通过。特意占用45300模拟未知进程，整套启动失败后回收本次模型/Backend/Vite，同时保留该监听器。连续两次debug:stop通过。Nano原生Group初始化与资源测试2个文件9条通过。

正常生产Chat/Nano PID保持不变、普通dev继续健康。全部自有调试服务已停止，端口释放；导航与diff检查通过。一次冒烟与主动重启重叠而连接中断，重启就绪后完整冒烟通过；不将这类主动中断描述成业务排空。GUI手工断点、真实账号、全新Linux生产机器不在本次实测范围。
