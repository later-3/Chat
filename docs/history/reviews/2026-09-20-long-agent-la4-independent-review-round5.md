# LA4 第五轮独立复核：第四轮问题关闭

2026-09-20。结论：**第四轮 2 个 P1 + 1 个 P2 均通过独立复验，本轮未确认新的生产可达阻塞问题。LA4 可按方案 B 的既定范围收口，下一步可准备 LA5 任务书。**这不是无缺陷保证，也不代替 LA6 的全天/渠道验收。

## 独立证据

使用隔离临时 CHAT_HOME、本地 HTTP 假模型、真实任务及产物服务，执行原第四轮三个探针和当前三套产物测试：**38/38 通过**（35 项既有测试 + 3 项独立探针，约 5.4 秒）。

1. 内部 `.chat-notes` 符号链接：拒绝，工作区外没有创建文件。
2. 旧维护在新修订后恢复：不回退版本文件路径/当前指针。
3. 处理旧冲突后产生新修改：旧选择清除，新冲突可重新处理。

代码核对：派生路径通过 authorizeNoteStore 授权；刷新在记录锁内比较 revision/contentHash/versionFile，并检查最新目标归属；冲突内容/来源变化使旧决定失效。按当前实现和上述复验，关闭第四轮发现。

## 额外探针：不作为当前产品缺陷

另构造两个直接 reconcileFriendArtifacts 调用并发，旧调用在读到 edit one 后暂停，新调用记下 edit two，再释放旧调用。底层函数在版本未变时会回写旧冲突；这个额外探针失败。

继续追踪生产可达性：当前源码仅由 tasks/service.ts 的 reconcileFriendTasks 调用该维护服务；该入口通过 activeMaintenance 按 Chat Home 合并在途任务。同一正常 Chat Home 的生产维护不会并发执行上述两个刷新。没有确认其他生产调用入口，故该直接函数级并发不计作新 P2，不要求为此扩大 LA4。本结论依赖现有单 Backend/同 Home 维护串行化边界；未来新增直接刷新入口或改变部署并发模型时需重新验证，不能忽略该条件。

## 验证范围与边界

本轮没有独立重跑全量 pnpm verify、真实浏览器或付费模型。实施者报告的完整门禁和浏览器结果保留为其证据，不冒称复核者亲测。此次确认的是本轮修复及相关确定性测试；没有提交、推送或部署。

方案 B 行为保留：用户可见 notes 文件只首次创建，此后不自动覆盖；当前生成内容以产物记录/前端当前版本为准，需要工作区副本时导出到新文件。这是已明确的产品取舍，不列为缺陷。

LA5 群聊、LA6 整天自然运行与外部渠道交付不计入本轮缺陷，也不由本轮通过推定已实现。
