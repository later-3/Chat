# 0.5.1 发布与界面统一批次核对

## 范围

用户授权整理文档、更新版本号、提交并推送，随后切一次发布：父仓库 `0.5.0` → `0.5.1`，Frontend `0.9.2` → `0.10.0`。本轮不更新本机正式服务、不迁移正式数据，也不在空白 Linux 主机执行 systemd 安装。

Pi 保持受管 Fork 的固定提交 `5b580155b`，基础包版本 `0.85.1`，不执行独立 npm 发布；NanoClaw 无修改，沿用 `c14d98d`。父仓库 `v0.5.1` 记录全部 gitlink。

## 后续：本版因字段契约错配被 0.5.2 取代

本版固定 Frontend `691bcfc`（0.10.0，已停止发送 `interactionRevision`），后端当时仍要求该字段，Friend 私聊一律 409；错配随 `56e2c6eeb` 修复并由 [0.5.2](./2026-09-29-release-0.5.2.md) 重新发布。原因与门禁见[经验案例](../../development/experiences/frontend-backend-field-contract-drift.md)。

## 变化与修复

- 任务与归档区域：`FriendInspector` 改为按日分块（今天恒定第一、块头会话/任务计数、会话直接列出名称·类型·时间、执行行可点开、空日期给一行幂等入口），历史日期由 `FriendCalendar` 浏览后选中加入，最多 7 天并按 Friend 持久化。区域为会话列左侧全高整块，Compact 覆盖会话列。
- 停靠面板统一：新增 `.workspace-dock` 原语（`--dock-width` 宽度、`--duration-panel`/`--ease-standard` 过渡、`is-open`/`is-closed` class 开合、内层固定宽不重排、`is-resizing` 关过渡），导航列表、项目资料、任务与归档三处共用；删除侧栏与资料面板各自重复的宽度/过渡规则。修复了两处缺陷：任务与归档此前为条件渲染，展开没有过渡，与项目资料观感不一致；`--dock-width` 曾写成相对值，被同时用于面板与内层后二次解析，把内容压成约 151px。
- 任务与归档为动画保持挂载，但只在展开时读取日历投影、任务、执行与项目名，关闭态不产生多余请求；关闭时 `inert` + `aria-hidden`。
- 工具栏动作：主导航、会话顶栏、分支导航默认仅图标，名称由 Hint 与 `aria-label` 提供；新增 `chat:toolbar-labels` 偏好（默认仅图标），设置可切「图标与文字」，Compact 保留可见名称。
- 动效与复用门禁：遮罩/浮层统一 Token 动效，按压态改用语义色而非 `filter`；`lib/motion-contract.test.mjs` 覆盖停靠面板复用与绝对宽度、工具栏动作唯一来源、遮罩淡入、动效 Token、`ui-*` 类存在性。
- 文档：Frontend UI/UX 规范升到 3.1（§20.6 停靠面板、§20.7 门禁）；`docs/modules/web/chat-web.md` 日期工作区改为顶栏动作 + 左侧全高按日区域 + 按需历史日期，并补工具栏图标规则；`docs/modules/long-agents/README.md` 移除 Web 面板「＋」创建入口。
- 本次顺带修复文档门禁：UI 审计页仍链接已被删除的 `FriendWorkPanel.tsx`，`check:architecture` 因此失败；链接改为带删除说明的纯文本（历史证据保留）。
- 标签之后的追加修正（Frontend `0.10.1`，`d5a8d7f`）：v2.3 art 方向把消息列改成 `--measure-prose`（42rem）后，输入框仍硬编码 880px、运行状态仍 820px，宽屏下会话区出现三条宽度和三条中心轴，输入框与上方消息明显错位。改为消息列、运行状态、输入框共用 `.workspace-composer-column`（同一 token、同一中心、ChatMinimap 的 36px 右侧沟槽由 `--composer-gutter` 表达，Compact 归零），并加 `lib/measure-contract.test.mjs` 与 UI/UX 规范 3.2 的对应条目。该修正不在 `v0.5.1` 标签内。

## 验证记录

- Frontend：`pnpm test` 243 项通过、`pnpm typecheck`、`pnpm build` 通过；生产包内确认带 `0.10.0`（`VITE_APP_VERSION`）。
- 父仓库本次在 macOS 开发机执行：`pnpm check:architecture` 通过（180 个入口、1640 条本地链接）、`pnpm typecheck` 通过、`pnpm test:tooling` 58 项通过、`pnpm test:backend` 673 项通过、`pnpm build`（Frontend/Backend/CLI）通过、`pnpm test:built` 30 项通过。合计 1,004 项通过、0 失败、0 跳过，日志在忽略目录 `.data/verification/release-0.5.1/`。
- 新增门禁：`scripts/deployment-config.test.mjs` 校验 `package.json` 版本、`docs/operations/release-<version>.md`、安装命令里的标签、验证记录页和四个入口文档的版本指针一致；0.5.0 页面指向未推送标签的问题不会再静默复发。
- `pnpm test:dev` 的浏览器场景未在本机执行（无 Chrome/无桌面栈）；父仓库工作区当时还包含与本次发布无关的在途改动，因此上述计数对应开发工作区，不等于标签上的完整 `pnpm verify`。权威门禁是父仓库 CI 在包含本提交的 `main` 推送上的 `pnpm verify`（Ubuntu，含浏览器场景）；标签本身不触发独立运行，目标平台安装仍由 chatctl 在机上执行同名命令。
- 标签与子模块：父仓库 `v0.5.1`、Frontend `v0.10.0`（提交 `691bcfc`）；Pi `5b580155b`、Nano `c14d98d` 沿用已推送提交。Frontend 随后在 `main` 追加 `v0.10.1`（`d5a8d7f`）；父仓库 `main` 的 gitlink 已指向它，`v0.5.1` 标签仍固定发布时的 `0.10.0`。
