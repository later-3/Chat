## 本次实现

1. 同事头像显示就绪、工作中、停用、未知的文字和标记；IM 单独显示。没有真实待用户记录，不展示黄色等待或离开状态。工作中包含当前后端锁中的排队操作；就绪不是模型健康检查。
2. 同标签页文字草稿恢复，设备/会话/项目隔离；发送文字保留至服务端明确确认，刷新后不确定时可手动核实恢复；附件仅内存保留，刷新明确提示缺失。失效会话链接不偷偷打开默认同事。最近位置使用窗口存储，前进后退按后端身份恢复。
3. 右侧增加同事只读资料和原配置入口；文件保留来源、最近标签及预览位置。动态阅读隐藏无关项目条；返回保留交流。
4. 增加标准/宽内容偏好；保留正文行长、调宽和折叠。抽屉及旧非原生配置模态层统一焦点、Escape 和返回；折叠区从辅助技术及 Tab 顺序移除。模型、Memory 与同事配置处理未保存离开；同事配置保留原 revision 冲突合同。
5. 删除无人消费的旧 Agent 菜单、移动综合菜单状态和自动命名处理函数；不删除新的有效入口。功能取舍继续见[功能去向清单](../../modules/web/chat-web.md)。

## 明确限制

- 真机 iOS/Android 软键盘、安装后的 PWA 与屏幕阅读器需要真实设备复核；桌面 Chrome 模拟不替代真机。
- 未接入统一配置失效通知，presence 可见时每 3 秒重读，超时 5 秒；不宣称毫秒级全局实时状态。
- 浏览器存储不可用/满额时保留内存草稿，但无法保证刷新恢复；附件数据不写入 sessionStorage。
- 确认前刷新只恢复待核实的输入记录，不据此推断服务器是否已收到。用户核对会话后手动恢复或清除，处理前禁止再次发送；不按消息正文猜测投递结果。浏览器存储限制仍适用。
- 同事“停止等待”不终止后端工作，不自动重发状态不确定的请求；没有新增离线发送或多窗口恰好一次提交合同。
- 文件树与预览共用一个资料面板，仍不能左右平铺；当前原生 Run/Session、资源和权限能力不因布局变更而扩张。
- 新任务、群聊、对外用户、自然语言实际切目录及未接入的 Git/更新/自动标题能力不在本轮范围。
