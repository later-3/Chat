# LA1 验收：Friend 独立后台工作

日期：2026-09-20。范围为用户授权的 LA1；实现合同见 [Long Agent 架构](../../modules/long-agents/chat-long-agent-architecture.md#la1独立后台工作实现合同)，阶段目标见[开发计划](../../development/long-agent-functionality-plan.md)。未部署、重启正式服务、提交或推送。

## 交付与实际使用

Friend 日常聊天侧栏新增“后台工作”，可填写名称和完整说明发起工作，也可要求已启用 `friend_work` 的 Friend 自己委托。工作列表提供状态、打开会话和停止入口，工作会话可继续提问、流式查看、刷新恢复、返回日常交流。默认受管能力包含该 Tool，用户显式配置的工具集合不会被强行扩展。

同一个 Friend 的身份与能力保持一致，工作各用独立 Pi Session，主聊可同时继续。每个 Friend 最多 4 条活跃后台 Session，同 Session 的消息依次执行。工作固定创建时的项目，切换顶部项目不改投已经开始的工作；接受时保存装配快照。结果保留在原生 Session，返回主聊只追加带来源的状态引用，不自动再次调用模型。

复用现有公共 Pi 装配、AcceptedTurn、Session 操作锁、事件流和聊天组件；没有第二套模型运行时或工作状态库。实际 Workflow 迟到返回已改为释放旧写入器后，在来源 Session 锁内重开、去重和写回。状态从 v4 兼容迁移到 v5，保留不可覆盖的迁移来源和完成标记。

## 自动化验证

完整 `pnpm verify` 在隔离源码及独立依赖副本执行：**620 项通过**，包括 44 项脚本、372 项后端、173 项前端、30 项 Built Server、1 项 Nitro dev。严格类型、架构导航、前后端和 CLI 构建同时通过。没有在正式工作区重建 `.output`。

LA1 新增 15 项后端业务测试、3 项前端合同/恢复测试。后端新增测试使用真实公共装配、Pi、Session 文件和本地 HTTP 假模型，覆盖：

- 后台与主聊并行、同工作有序、并发接受最多 4 项；取消主聊或工作不误取消另一方。
- 同请求重试收敛、异载荷拒绝、其他 Friend 身份/递归创建/改投项目拒绝。
- 装配期间取消不再调用模型；独立 Node 进程恢复 queued，保留旧项目规则；未知 running 标 interrupted，不重放工具。
- 真实 Workflow 写入器等待父锁后重开最新分支；重复返回只有一个收据；已关闭旧日不重开，删除来源不复活。
- 新尝试失败不拿旧答案冒充结果；受控 edit 的整个读改写互斥；注册工具从可信身份委托。

执行中发现并修复的问题也纳入最终门禁：工具注册表期望需要包含新 Tool；Friend Tool 静态导入生命周期产生 Nitro dev 装配环，改用既有管理工具采用的执行期导入并通过 `test:dev` 重验；并行脚本测试中假服务实际约 13.4 秒才就绪，原 10 秒测试预算不足，改为 30 秒有界就绪等待，未更改产品启动逻辑。

## 8 项自检及边界

| 检查 | 结论与边界 |
|---|---|
| 需求完整 | 通过。API、注册 Tool、真实 UI、取消/状态/结果入口均已交付；没有只建立 Session 文件后声称后台工作可用 |
| 架构一致 | 通过。公共装配和原生 Session 保持单一；Friend Home 保存私有工作历史，业务项目是冻结的协作上下文 |
| 事实与权限 | 通过。稳定工作/来源引用、接受快照及 Tool 可信身份可回读；未放开递归委派或任意 Friend/项目伪造 |
| 生命周期 | 通过本阶段测试。失败、取消、重启、重复/迟到、跨日/删除来源均有结果；不自动重放未知副作用。既有 Workflow 超时返回后可按 callId 查询持久 Run；重启后不是新增后台全局 Workflow 回执调度器 |
| 并发 | 通过。主聊不占后台 4 项额度；同 Session 串行。文件保障限单 Backend 受控 write/edit，Bash/扩展/外部进程并发写同文件须独立工作副本；没有宣称跨进程事务 |
| 可用性 | 通过。共用聊天流、历史和输入；侧栏状态每 3 秒更新。网络丢回执保留原请求供显式确认，不自动重新创建 |
| 验证诚实 | 通过。明确区分 620 项自动化、真实模型、真实浏览器与未测渠道；修复验收实际发现的问题后再给结论 |
| 最终目标 | 通过。独立工作与每日主聊分离，为任务与群聊提供执行基础；三项长期学习、每日 3+1 发布及群聊尚未实现，不能冒充本阶段能力 |

另一个明确边界：原生工作绑定和首次接受是可恢复的两步持久化，接受失败时列表可能出现 execution 为 null 的待确认项；页面保留原请求重试，不把它显示为运行成功。跨日结果留在后台列表，不自动唤醒新一天主聊。LA2 接续任务 CRUD、触发和 Occurrence 管理，LA3–LA5 接续职责、动态和群聊。
