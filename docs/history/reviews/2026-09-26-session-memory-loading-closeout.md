## 本次复核实际修复

1. **关闭记忆后 HTTP 请求被拒绝。** 旧浏览器用例只检查请求参数和 writer 没运行，HTTP 400 也会满足断言。补齐 Long Agent `POST /turns` 对 `sessionMemory` 的校验与转交，并补齐耐久 turn 解析对 `off` 的支持。关闭记忆现在仍能正常执行工作阶段。新增后端真实路由回归，检查 202、耐久状态、工作完成和非法值拒绝。
2. **导航缓存会被轮次后的历史同步误用。** `useAgentSession` 区分首次导航读取与刷新；只有导航可以消费预加载结果，轮次结束、恢复及轮询必须读取服务端最新消息，避免旧快照覆盖刚生成的答案。
3. **复用已打开会话时未切回聊天视图。** `AppShell` 的同会话快捷分支仍调用共享选择入口以显示聊天；复用会话状态不等于跳过导航。

## 浏览器业务证据

`scripts/session-memory-switch-browser.test.mjs` 现在在同一个页面、同一个会话内依次验证：默认开启发送 → 关闭发送 → 真正刷新后首次发送仍关闭 → 重新开启发送 → 去主题视图再打开同一 Friend → 记忆失败后保留答案、显示通知 → 刷新后通知与答案仍可见。

每次发送均核对真实请求体、HTTP 接受结果、执行终态、writer 调用次数以及本轮独有答案在可见聊天中出现；同时验证轮次后的刷新没有复用导航旧快照。请求被拒绝不再可能冒充“成功关闭记忆”。
