## 交付与事实拥有者

- `src/agents/session-events.ts` 是公共 Pi 事件投影；Workflow 发布器和 Friend 生命周期复用。
- Friend Web 通过 turns API 耐久接受并取得稳定引用，然后订阅；沿用 P3 队列和原生 Pi Session，不另起 Workflow 或消息数据库。旧 messages API 保留兼容。
- `execution-stream.ts`、同一个 handleRunEvent、streamReducer、runActivity 和消息组件处理两个入口。Friend 适配器只处理接受、快照、连接恢复和操作能力，Workflow 继续携带真实 stage/review。
- 快照替换、事件序号去重、256 条窗口 reset、15 秒无响应重连；恢复只 GET，不自动重发。终态从耐久执行读取，最终历史重读 Pi。
- 显式停止调用实际取消；同项目原生 steering、跨项目后续消息和有序耐久队列已接通。图片使用实际模型能力；页面导航仅离开观察。
- 公共读模型将原生压缩/分支摘要转换为已有 custom 展示消息，保留原生记录与 Entry 对齐；两个入口均受益。

## 阶段自检与修复

1. **没有只做最终回复**：后端直接发布 Pi 增量；同一 renderer 显示工具/重试/压缩，浏览器录得多次内容增长。
2. **没有浏览器事实库**：耐久接受和 Session 属于 Backend/Pi；活跃缓存仅是有界投影与取消句柄。重连/切页不 POST。
3. **没有用断开冒充取消**：DELETE 到原生 abort；取消与后续请求独立，原有 workflow_call signal 传播保持。
4. **没有只测正常路径**：修复 turnId 中冒号的路由解码；过期事件 reset、无响应重连、非法合同不无限重试、消费中的引导不能假称可撤回。
5. **发现后修复再验收**：浏览器实际发现原生压缩摘要角色与 Web 合同不符；修复公共读模型并增加回归和[经验资源](../../development/experiences/native-summary-web-projection.md)。最终重新跑完整门禁，再在新构建完成压缩后继续/刷新及真实模型切页恢复。
6. **能力差异公开**：普通 Workflow 的引导/后续原来只会报“不支持”，现不显示假入口，输入草稿保留；Friend 已实现这两种操作。手动压缩没有新开通，自动压缩可观察。无已实现能力被删除；Workflow 审核与阶段不移除。
7. **文档与最终目标**：模块合同、前端开发规范、Long Agent 架构、Context、路线图、测试入口和计划同步。P4 的 S01/S04/S07/S08/S10 及 S12 布局/旧 URL 部分已验证；全量旧数据迁移和真实 Telegram/Nano 外部收发按原计划留在 P5，没有把它们写成已验收。

P4 的执行、界面、失败恢复和文档边界已闭环，下一阶段为 P5 迁移与全链验收。
