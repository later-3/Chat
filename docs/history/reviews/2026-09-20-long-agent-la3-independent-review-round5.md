# LA3 第五轮独立复核：旧条目可信性仍不能由指针相等推断

2026-09-20。范围为升级读取、实际模型输入、反复读写、旧格式跨目标条目。未修改业务代码、提交或部署。

## 方法与结果

独立探针 3 项：1 通过、2 失败；现有职责门禁 27/27 通过。隔离 Chat Home、测试模型 HTTP 服务和 Nano 投影替身，调用实际职责服务与公共 Pi 执行链。所有输入结论均检查真正发送到测试模型服务的请求，不只调用字符串组装器。没有声称真实模型、浏览器或生产升级验收。

证据：`.data/verification/la3-review-round5/independent.log`、`existing.log`、`probe-source.mjs`。源码原运行位置为 `test/long-agents/la3-round5-independent.test.mjs`，重跑时按该位置解析相对 import，结束后移除临时文件。

## 通过：三轮升级读—实际写—再读取—模型执行

用实际服务先产生用户纠错与 reportApplied=false 的后台迟到报告，再将隔离存储转换为上一版无 applied 的格式。两条报告的指针值不同。连续三轮读取、暂停/恢复（实际写回）、重新推进，当前完成量保持 8；拒绝条目保持 applied=false；每次模型请求含可信摘要、不含拒绝摘要。写回后的显式标记稳定。

## R5-1 / P2：相同指针不足以证明摘要和证据曾被应用

位置：`src/long-agents/duties/contract.ts:130` 附近的 `same` 与 `verified` 选择。

独立复现：真实服务产生一条用户纠错（TRUSTED_SUMMARY）和其后后台报告（REJECTED_SUMMARY）。两者 unitsDone=8、nextStep=CURRENT_NEXT、nextCheckAt=null，但后台执行对应旧 revision，服务明确返回 reportApplied=false。恢复成上一版无 applied 的格式后重新加载，算法选择较新的后台报告，分类从可信/历史变成 `[false,true]`。实际下一轮模型请求出现 REJECTED_SUMMARY。

这不是已修的“值不同”案例重复失败，而是判定依据不足：三个指针相等不能证明摘要、证据、来源或应用结果相同。不能把字段匹配称为可靠验证。

修复门槛：使用真实可验证的应用关联、修订或审计证据；若旧格式没有足够信息，不猜测，保留历史并标记未核验、禁止作为当前依据。保留权威当前指针；需要重新确认时明确提示。不能再用“最新匹配条目”作可信性的替代。

## R5-2 / P2：跨目标候选抢占当前依据

位置：同一 `verified` 搜索未限定目标代号。

独立复现：旧格式 dutyRevision=2 的当前目标条目与 dutyRevision=1 的迟到旧目标条目，三个指针值恰好相同，旧目标条目时间较晚。迁移选择旧目标条目 applied=true，当前目标条目 applied=false；随后组装按目标过滤掉旧目标，实际模型请求既没有 OLD_GOAL_FACT，也没有 CURRENT_GOAL_FACT。

旧目标内容没有泄漏进当前目标，这一点通过；失败是旧目标候选改变了当前目标依据的判定，使当前依据无声丢失。不能仅按“不含旧摘要”判全部通过。

修复门槛：每个目标的可信性和当前状态独立处理，不让跨目标条目争抢唯一匹配位置。若采取全部未知历史保守隔离的方案，应明确当前指针仍保留但依据待核验，不能声称“尚无记录、第一次推进”或自动重新学习。此项不要求对无法证明的当前条目强行标为可信。

## 判定与下一步

稳定读写已通过，剩余两个失败都来自同一个迁移可信性推断，不需要修改已通过的调度/CAS。建议停止继续增强字段相等启发式，采用“有可验证应用证据才恢复可信，否则明确未知历史”的合同。修复后验证相同指针不同内容、跨目标、普通旧记录和多轮读写下的实际请求，并同步说明无法无损恢复的旧格式限制。LA3 完整验收仍待该项通过。
