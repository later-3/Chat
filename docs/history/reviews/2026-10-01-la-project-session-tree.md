# 2026-10-01 Long Agent → Project → Session 三级导航与项目归属会话（合同评审）

## 背景

用户确认把 Web 端会话入口从"Friend 直接会话 + 顶栏项目选择器"重构为三级导航：Long Agent → Project → Session。Long Agent 通过显式绑定参与多个项目；每个项目下展示、新建、继续该 Long Agent 的 Session。主题模式本期只做项目下展示（沿用现有创建流程），跨项目来源放宽与交互式创建体验后置。

## 决策

1. **绑定关系**：`LongAgentConfig` 新增有序 `boundProjectIds`，增删走现有配置 API 与 revision。校验：项目必须已注册、去重、Agent Workspace 固定首位且不可解绑。解绑只移除导航可见性，不删除该项目下的 Session。绑定是 LA 配置，不是"第二套可写的项目关联存储"。
2. **项目归属会话**：从绑定项目新建的 Web 会话 `storageProjectId` 为该项目，每轮执行项目 = 会话归属（与群聊轮次现行规则一致，受理时冻结）。每日默认、额外直接会话、定时任务与 IM 轮次仍归 Agent Home，入口不变。旧 Session 不迁移。
3. **身份保证**：复用现有三层机制，不新增运行时——SessionRef `ownerKind/ownerId` 归属校验；公共装配按各 LA 独立配置根冻结身份区与当前项目区；前端导航路径本身标注身份。
4. **退役顶栏选择器**：新导航落地后删除顶栏"项目"选择器及 URL `projectId` 覆盖；装配合同中"私聊按顶栏选择冻结"的现行描述在实施任务完成后同步改写。
5. **主题模式范围**：本期只在项目下展示主题图（只读接线现有视图）；建节点仍走现有流程与授权；跨项目来源放宽后置到下期。

## 架构影响评估

- 无新增运行时、无第二套 Session 事实源；Session 仍由 Pi 保存，公共装配、授权与每 Session 队列不变。
- 归属唯一性红线不破：一个 Session 一个归属；切项目/解绑不迁移 Session；不存在第二个可写的"项目关联"存储。
- 变更集中于：LA 配置 schema + 配置 API、会话打开/列表服务的归属解析、前端信息架构。装配链仅 `contextProjectId` 的传值来源变化（顶栏 → 会话归属）。
- 合同落点：Context §15.6 与 Long Agent 架构 §4.1 增补目标合同；实现完成后回写 §15.1 表行的统一项目合同描述。

## 实施任务与阶段

任务 1 合同（本记录）→ 2 绑定 → 3 项目下建/续/列 Session → 4 前端三级导航 → 5 退役顶栏选择器 → 6 浏览器端到端验收。三阶段门禁：`pnpm verify` + 三仓库 `git diff --check`；阶段三浏览器用例进 `pnpm test:dev`。

## 验收口径（最终效果）

1. 添加项目与现有项目注册流程一致，仅入口移位；
2. 项目内 Session 展示与管理与现 Projects 会话列表同一套能力；
3. 从当前上下文交互式新建 Session 先接现有能力；主题模式深度优化后置。
