# Chat 设计规范

> 版本：v1（摸着石头过河版）。本规范是所有界面任务的强制约束；色值与数字允许迭代，但**只允许改本文件的值表和对应 Token 定义，不允许在组件里写死**。违反第 8 节检查清单的实现评审不通过。

## 1. 设计参照

| 产品区域 | 参照对象 | 取什么 |
|---|---|---|
| 整体骨架与品牌气质 | **Threads** | 黑白高对比中性骨架；界面几乎不铺彩色；设计感来自排版、留白、hairline 和结构，不来自装饰 |
| 对话区布局 | **ChatGPT** | 消息流、底部输入区、回车发送的熟悉交互模式 |
| 工作流看护区 | **Things 3 / Apple 备忘录 / Fantastical** | 清单与步骤的状态表达、"当前进展"的节奏感、克制的结果摘要 |
| 设置区（后续任务） | 笔记与日历软件的设置模式 | 分组列表、分级背景、清晰的层级 |
| 未来社交形态（现在不做） | 社交软件动态流与群聊 | 未来多 Agent 各有身份、事务、动态；视觉系统必须预留"Agent 身份色"扩展位 |

交互与可访问性底座遵循 Apple Human Interface Guidelines，并按第 3～6 节钉死为 Web 可执行数字。

### 不做的事

1. 不使用紫蓝渐变等"AI 产品套路色"。
2. 不用大面积彩色背景、重阴影、粗边框表达层次。
3. 不为当前不存在的能力预建组件（如 Agent 动态卡片），只预留 Token 扩展位。

## 2. 主题系统：浅色与深色双主题

### 2.1 品牌色 = 黑白反色

Chat 的品牌色就是黑白本身：

- 浅色主题：主按钮、选中态、强调文字用近黑 `#1D1D1F`。
- 深色主题：反转为近白 `#FFFFFF`。
- 链接用文字颜色 + 下划线表达，不依赖色相。

彩色只出现在两种地方：**状态色**（成功/警告/失败，见 2.4）和未来的 **Agent 身份色**（见第 7 节）。

### 2.2 语义 Token 架构（强制）

组件代码只允许引用语义 Token，禁止出现具体色值。Token 分三层：

1. **背景层**：`--bg-primary`（页面主背景）、`--bg-secondary`（分区/卡片）、`--bg-tertiary`（悬浮/按压）、`--surface-raised`（凸起层：选中分段、浮层）。
2. **文字层**：`--text-primary` / `--text-secondary` / `--text-tertiary`。
3. **结构与状态**：`--separator`（发丝分隔线）、`--accent` / `--accent-text`（黑白反色强调）、`--status-success` / `--status-warning` / `--status-danger`。

### 2.3 中性色值表（v1）

| Token | 浅色（纸感白） | 深色（真黑） |
|---|---|---|
| `--bg-primary` | `#FFFFFF` | `#000000` |
| `--bg-secondary` | `#F5F5F4` | `#161617` |
| `--bg-tertiary` | `#EBEBE9` | `#242426` |
| `--surface-raised` | `#FFFFFF` | `#2C2C2E` |
| `--text-primary` | `#1D1D1F` | `#F5F5F7` |
| `--text-secondary` | `#6E6E73` | `#98989F` |
| `--text-tertiary` | `#9B9BA0` | `#6C6C72` |
| `--separator` | `rgba(29,29,31,0.10)` | `rgba(245,245,247,0.14)` |
| `--accent` | `#1D1D1F` | `#FFFFFF` |
| `--accent-text` | `#FFFFFF` | `#000000` |

深色主题用真黑 `#000000` 打底：OLED 屏幕上最省电、最酷，靠 `--bg-secondary/tertiary` 的浅灰分层表达悬浮层级。

### 2.4 状态色（v1，需过对比度校准）

| Token | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--status-success` | `#248A3D` | `#30D158` | 已完成、正常连接 |
| `--status-warning` | `#A85B00` | `#FF9F0A` | 等待、需要注意 |
| `--status-danger` | `#C22F3D` | `#FF453A` | 失败、错误 |

规则：状态语义**永远文字 + 图标/形状 + 颜色三通道**，任何状态不允许只靠颜色区分（可访问性硬条款）。

### 2.5 主题切换机制

1. 默认跟随系统（`prefers-color-scheme`）。
2. 顶栏提供手动切换按钮（太阳/月亮图标），触控目标 ≥44px，带可访问名称。
3. 手动选择写入 `localStorage`（键 `chat-theme`，值 `light|dark`）；这只是界面偏好缓存，不是产品事实。
4. 防闪烁：`index.html` 内联一段启动脚本，在首屏渲染前读取偏好并向 `<html>` 写入 `data-theme`；CSS 变量按 `[data-theme]` 与系统媒体查询两层定义。
5. 切换过程不做全局过渡动画（避免整页闪烁感），仅状态图标本身可有短动效。

## 3. 排版

1. 字体栈：`-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Helvetica Neue", "Segoe UI", sans-serif`。不引入 Web 字体依赖。
2. 字号梯度（v1）：13（辅助）/ 15（正文）/ 17（标题）/ 20（页面标题），行高约 1.4–1.5。
3. 字重只用 400 / 600 两档；强调靠字号与字重，不靠斜体或颜色。
4. 数字与状态对齐场景使用 `font-variant-numeric: tabular-nums`。

## 4. 间距、圆角与层次

1. 间距只能取 4 的倍数：4 / 8 / 12 / 16 / 24 / 32。
2. 圆角分级：按钮与输入框 10；卡片与面板 14；消息气泡 18。
3. 层次靠"背景分级 + 1px hairline 分隔线（`--separator`）"表达；禁止默认阴影，深色主题禁止发光式阴影。
4. 可点/可触目标最小 44×44px（手机端硬条款）。
5. 顶栏与输入区可使用轻微 `backdrop-filter` 模糊 + hairline 底线；其余区域不滥用毛玻璃。

## 5. 动效

1. 只用于状态过渡，时长 150–250ms，缓动 `ease-out`；不使用弹性夸张动效。
2. 必须尊重 `prefers-reduced-motion`：命中时取消非必要动效。
3. 工作流状态变化不使用持续循环动画打扰用户（允许一次性脉冲或静态图标）。

## 6. 可访问性硬条款

1. 正文文字对比度 ≥ 4.5:1；大字号与交互元素 ≥ 3:1（WCAG AA）。新色值进值表前必须校准。
2. 键盘可达所有交互元素；焦点清晰可见，禁止 `outline: none` 无替代。
3. 图标按钮必须有可访问名称（`aria-label`）。
4. 状态区域使用语义化名称与克制的 `aria-live`，不制造频繁播报。
5. 状态表达三通道：文字 + 图标/形状 + 颜色。

## 7. 未来扩展预留

1. **Agent 身份色**：从暖色系色族（珊瑚、橘、黄、粉）为每个 Agent 分配身份色，用于头像、发言标识与动态卡片。产品骨架保持黑白，Agent 是画面里的彩色——这是"沉静产品 + 鲜活 Agent"的长期层次。
2. **社交形态**：动态流、群聊等界面现在不设计，但新增组件时必须能用现有语义 Token 表达，不得为单个区域发明一次性色值。
3. 品牌场合（如启动画面、官网）允许使用暖色渐变；**产品界面内禁止渐变**。

## 8. 评审检查清单

实现评审时逐条核对，任一不满足即不通过：

1. 组件中无硬编码色值、字号、间距、圆角；全部来自 Token。
2. 浅色 / 深色两套主题均渲染正确，切换无闪烁、无假状态。
3. 对比度过 AA；焦点可见；图标按钮有可访问名称。
4. 状态不只靠颜色表达。
5. 动效克制且尊重 `prefers-reduced-motion`。
6. 无渐变、无重阴影、无紫蓝"AI 色"。
7. 375px 无横向滚动；触控目标 ≥44px。
