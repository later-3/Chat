# Chat UI/UX 视觉基线 v1

## 1. 状态与用途

| 项目 | 内容 |
|---|---|
| 决策状态 | 2026-07-24 用户审核通过 |
| 适用范围 | Chat Web 的个人主页、连续对话、协作日历、灵感花园、Workbench、审批和配置界面 |
| 当前实现 | 可交互原型已形成；本文件批准的是后续生产前端采用的视觉与情绪方向，不表示整套生产界面已经迁移完成 |
| 原型位置 | `prototypes/chat-uiux-v1/` |

这套基线的目标不是先完成一次重品牌，而是在不拖慢核心产品能力建设的前提下，让Chat具备清晰、有温度、有适量趣味且可以长期使用的产品气质。

## 2. 视觉方向

1. 以Material 3 Expressive的形状、色彩、层级和动效思想作为影响来源，不照搬Google产品。
2. 主色使用自然绿和青绿色；珊瑚橙、暖黄、浅蓝作为情绪色和区域色。
3. 使用暖中性色表面，避免紫色、AI渐变、冷灰后台感、密集边框网格和无意义装饰。
4. 信息密集时依靠层级、渐进披露和空间组织，不通过缩小正文强行塞入一屏。
5. 首页和灵感空间可以更有生命力；对话保持温暖安静；Workflow、日志和ExecutionDraft保持克制精确。
6. 动效必须解释状态、因果或空间关系，并支持减少动态效果；不建立仅用于装饰的动画系统。

## 3. 轻量情绪层

后续前端实现优先加入以下4项，不等待完整主题系统或品牌重构：

### 3.1 有记忆的主页问候

主页问候来自Product Harness已经确认的事实，例如最近推进的Project、Work、学习目标或下一行动。没有可靠事实时使用中性问候，不能让模型编造用户状态。

### 3.2 关键动作反馈

只在真实状态发生变化时提供颜色、图标、短文案和轻微动效，例如：

- Idea候选已保存；
- 已采用昨天的Project Context；
- Workflow正在等待用户决定；
- Work通过验证；
- Daily Journal候选已生成。

反馈文案必须区分“候选、已接受、已执行、已验证”，不能把准备完成冒充事实完成。

### 3.3 可感知的AI运行状态

界面用公开运行事实表达“正在理解、寻找相关内容、等待决定、执行、验证、完成但需注意”等状态。视觉变化可以使用呼吸、流动或形状变化，但不得展示或暗示模型隐藏推理。

### 3.4 有生命感的协作日历

协作日历表达用户与Chat当天发生了什么，而不是生产力评分：

- 有有效Interaction时出现活动标记；
- Project或Work有真实推进时增强形态；
- 产生Artifact或接受知识时增加可区分的层次；
- 接受Idea时出现独立语义标记。

每个视觉状态都必须能展开到可核验来源。Token、模型调用次数和停留时长只属于二级用量信息，不能决定用户“做得好不好”。

## 4. 场景强度

| 界面 | 主要感受 | 表达强度 |
|---|---|---|
| Personal Home | 欢迎、重新定位、愿意继续 | 较高 |
| Activity Calendar / Idea Garden | 发现、成长、回顾 | 较高 |
| Continuous Chat | 陪伴、专注、自然表达 | 中等 |
| Workflow Run View | 掌控、解释、可恢复 | 克制 |
| ExecutionDraft / Approval | 清晰、可信、后果明确 | 克制 |
| Configuration Center / Trace | 精确、可查、低干扰 | 最低 |

“有趣”不等于所有界面都热闹；情绪强度必须跟随用户当前任务。

## 5. 延后但不取消

以下能力保留在后续设计演进中，不阻塞当前产品开发：

1. 多套可切换主题及完整主题编辑器。
2. 专属插画和品牌资产系统。
3. 复杂自定义动效引擎。
4. 游戏化积分、徽章或连续打卡机制。
5. 大规模品牌重塑。

这些能力进入实现前，仍需说明用户价值、状态来源、无障碍策略和维护成本。

## 6. 验证门

生产前端采用本基线时至少验证：

1. 桌面与窄屏的核心信息层级、键盘操作和焦点恢复。
2. 正文可读性、对比度、减少动态效果和非颜色状态表达。
3. 所有情绪反馈都能追溯到真实产品状态，刷新后不会与服务端事实漂移。
4. Workflow、Approval和Trace的精确语义不因视觉包装而弱化。
5. 页面仍满足当前Feature加载边界和生产包体门。
