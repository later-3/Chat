# Agent 工程治理规范

> 版本：`agent-engineering-standard.v0.2`。这是跨项目基础规范；目标 Workspace 的合同和工程规范负责
> 补充领域不变量、架构边界与实际命令。`必须`表示默认不可省略；`应当`表示除非有记录的理由，否则遵守。

## 适用边界

本规范适用于 Agent 参与的设计、实现、重构、调试、测试、审查、委派和交接。它约束的是 Agent
怎样推进项目，不替代当前用户授权，也不把某个语言、框架或目录结构推广成通用答案。

每条规则区分规范内容、生效机制、载体和证据，并把迁移结论分为：**核心规则**、**条件规则**、
**项目合同**、**观察**和**明确拒绝**。核心规则跨项目默认适用；条件规则只在写明的触发条件成立时适用；
项目合同由目标 Workspace Overlay 拥有；观察不得作为完成门；明确拒绝不得作为默认方案。

`必须/应当`描述义务强度，不表示载体已经机械阻断。只有 Agent 外的控制点实际限制动作，或受保护采用门
实际读取检查结果时，才能称为阻断；当前载体不足时仍必须如实报告。

本文件拥有跨项目的 Agent 推进规范；Chat 现有 `AGENTS.md`、技术合同和工程规范仍拥有 Chat 专属
Overlay，并在收敛期保留部分早期同义条款。发生冲突时不得自行合并：Chat 任务先遵守较具体的
现有合同，再把重复或冲突登记为后续收敛候选。Prompt Fragment 只是本规范的运行摘要投影，不是第三份规范事实源。

## 规则分类与 v0.2 采用结论

当前载体、触发时点和目标加强方向只由[治理 Map](./README.md)路由，本文件不复制运行矩阵。v0.2 收敛的是
规范内容，不会因为文字升级而自动增强 Prompt、检查器、权限或采用门的实际强度。

| 经验结论 | 规范位置 | 分类与触发条件 |
|---|---|---|
| 稳定核心、窄接缝和真实核心归属 | S3/S5 | 核心规则；拒绝用 LOC、文件数或把复杂度移入无治理扩展来冒充“小核心” |
| 接缝与共享可观察 Oracle | S7 | 条件规则；接缝存在多个实现或属于高风险边界时触发 |
| 可确定约束下沉，语义问题升级裁决 | S7/S10 | 核心规则；检测结果只有进入采用门才可能阻断 |
| 按失败模式和消费者差异组织验证 Lane | S7 | 核心规则；具体 Lane、命令和付费/真实门属于项目合同 |
| 依赖、Skill、生成链和发布工件的供应链治理 | S5/S10 | 条件规则；引入或变更这些工件时触发，不复制某个包管理器方案 |
| 候选、确定性验证与最终采用分离 | S8 | 核心规则；具体 Product Commit、Decision 或人类裁决属于项目合同 |
| 升级、迁移和发布晚于恢复、迁移与消费者验证 | S9 | 条件规则；外部结果未知仍由 S11 对账合同处理 |

低风险任务可以由受保护的确定性门加实现者自审完成；高风险任务必须增加未实现该变更的主体复核。

## S1 授权与任务合同

**目标失败**：Agent 把计划、历史任务书或自己的判断当成授权，持续扩大范围。

**要求**：

1. 开工前必须确定当前用户结果、不做事项、事实所有者和完成门；不明确但不影响结果的细节可以作最小假设并记录。
2. 研究、计划和阶段顺序不能自动授权实现、下载、外部调用、push、PR、部署或删除。
3. 新发现若实质改变用户结果、风险或外部副作用，必须暂停该分支并重新取得决定。

**证据**：一份可定位的任务合同或计划；实际差异与合同的逐项核对；所有扩展范围的批准记录。

**例外**：纯只读回答可以缩短任务合同，但不能省略权限和事实边界。

## S2 事实源与规则选择

**目标失败**：Agent 依赖陈旧摘要、一次性读完大量文档，或在冲突事实中自行选择有利版本。

**要求**：

1. 必须先读取最接近当前对象的源码、Schema、测试和 as-built，再按本 Map 选择相关规范；不要求无差别加载全部文档。
2. 当前实现、目标设计、历史经验和用户授权必须明确区分。
3. 两个权威来源冲突时，必须报告冲突及影响，不能让偶然实现或较新的文字静默胜出。
4. 引用外部项目时必须固定项目、版本或历史阶段，并区分作者主张、源码事实和我们的推论。

**证据**：任务实际使用的来源清单、关键版本/Commit、假设与未确认项。

## S3 设计与复用

**目标失败**：Agent 先写代码后寻找理由，复制成熟能力，或在没有真实变化时制造抽象。

**要求**：

1. 设计前必须写清用户可观察结果、约束、事实所有者、失败/恢复路径和完成边界。
2. 通用能力应当先检查可持续上游、公开接缝、许可证、维护状态、退出路径和故障边界，再决定直接使用、窄适配、拒绝或自研。
3. 核心或共享层只应容纳由该层事实所有者负责、对其合同成立所必需或被多个消费者共同需要的稳定语义；
   可选或高变化能力应经具有明确所有者、退出路径和验证的窄接缝外置，但不得转移产品事实或形成无治理的
   插件、Adapter、Skill 或生成增量。
4. 新接口、层级或扩展点必须由当前真实消费者、已发生的第二种变化，或必须隔离的不稳定边界证明；不能只以“以后可能需要”为依据。
5. 方案必须明确非目标，并说明为什么它是满足当前结果的最小完整方案。

**证据**：设计/复用结论、核心归属、接缝所有者与退出路径、候选对比、被拒方案及原因、失败与恢复路径。

## S4 分解与所有权

**目标失败**：多 Agent 重复劳动、同时修改同一事实源、交接丢失或由无人负责的集成阶段制造错误。

**要求**：

1. 一个任务应当只有一个主要结果；拆分以独立输出、依赖关系和可验证完成边界为依据，不以制造更多 Agent 为目标。
2. 并行优先用于只读调查、独立方案和互不重叠的验证。并行写入必须使用独立 worktree，或声明互不重叠的文件/模块所有权。
3. 同一个合同、迁移、锁文件或其他共享事实在同一集成阶段只能有一个写入所有者；冲突流必须串行。
4. 每组并行工作必须指定唯一集成者。子 Agent 的结果是候选，只有集成者核对基线、差异和证据后才能采用。
5. 交接必须包含基线 Commit、范围、变更面、假设、证据、未验证项、风险和建议集成顺序。

**证据**：任务/依赖图、写入所有权、worktree/分支、结构化交接和采用记录。

## S5 变更预算

**目标失败**：Agent 用新增文件、抽象、依赖和治理资产堆出功能，项目只增长不收敛。

**要求**：

1. 实现前必须列出预计触达的模块，以及是否新增生产文件、依赖、公共 API、持久格式、配置、Workflow 或治理规则。
2. 实现后必须比较预计与实际变更面；任何未计划的公共 API、依赖、持久事实或跨模块扩张都要停止采用，直到获得解释和批准。
3. 行为变更不得夹带纯风格重写、无关重命名或顺手重构。需要的结构修整应与行为变化具有直接因果关系。
4. 新增能力前必须搜索已有实现；新增代码时同时检查可以删除、合并或替换的旧路径。
5. 数值阈值用于触发审查而不是机械拆分。超过阈值时必须记录为何保留、单一责任、失败边界和测试证据；
   总 LOC、文件数和目录层数不得作为“小核心”或质量的替代指标。
6. 引入或变更依赖、Skill、代码生成链或发布工件时，必须记录可定位的来源与版本、可执行安装或生成面、
   升级与退出路径及验证方式；生成物必须由受审生成器再生并由一致性检查证明，不得直接手改。固定来源只缩小
   静默漂移，不免除主动升级和安全维护；来源或 Provenance 也不能替代质量证据。

**证据**：计划/实际文件与概念差异、新增/删除统计、新依赖与公共面清单、保留大模块的责任说明；适用时还包括
供应链来源/版本、安装或生成执行面及生成一致性结果。

## S6 代码与抽象

**目标失败**：代码能运行但难以理解、变化原因混杂、失败被隐藏或接口比实现更复杂。

**要求**：

1. 模块边界必须对应事实所有权、变化原因、事务、失败恢复或真实替换接缝，而不是按名词机械分层。
2. 优先保持小而稳定的公共面，把必要复杂度封装在内部；只转发一个实现、没有策略价值的接口应当删除或内联。
3. 错误、取消、超时、并发、部分成功和未知结果必须具有明确语义，不能通过宽泛 catch、默认成功或盲重试隐藏。
4. 重复代码只有在共同变化已经出现时才抽象；语义相似但所有权或失败方式不同的代码不得强行统一。
5. 完成前必须做一次简化审查：删除死路径、调试脚手架、重复 helper、无消费者导出和过期注释。

**证据**：公共面和消费者、边界理由、失败测试、简化前后差异；语言专属规则由 Workspace 工程规范补充。

## S7 风险与验证

**目标失败**：Agent 只证明 happy path、用 Mock 冒充真实边界，或根据旧输出宣布完成。

**要求**：

1. 编码前必须把主要风险映射到验证 Lane：纯规则、Schema、状态/并发、Adapter、真实服务、浏览器、消费者、
   发布工件或恢复场景。每个 Lane 必须声明它证明的风险、授权或成本要求、触发条件和未覆盖项；本地 Agent
   运行当前授权下的最小充分 Lane，最终采用必须满足目标 Workspace 声明的完整完成门。
2. Bug 修复必须先形成能识别该缺陷的回归证据；不能只修改实现并依赖既有测试偶然覆盖。
3. Mock 只证明调用合同。任务声称真实 Workflow、Provider、浏览器、存储或外部接缝成立时，必须使用相应真实或合同级证据。
4. 验证应当优先覆盖失败、恢复、边界和兼容；覆盖率数字不能代替测试价值。
5. 完成声明必须基于当前 Commit/工作树上新鲜运行的命令和完整输出。零测试、跳过测试或未运行不能写成通过。
6. 时间、随机数、网络、端口、共享目录和全局状态必须被隔离或显式控制；flaky 失败不得靠重复运行直到变绿来掩盖。
7. 测试优先断言用户可观察合同和稳定接缝；接缝存在多个实现或属于高风险边界时，所有适用实现必须复用同一
   基础合同或 Conformance Oracle，并分别覆盖风险相关的顺序、失败、幂等、并发、装配与运行时差异。类型只证明
   形状；除非调用顺序本身就是合同，不冻结内部实现步骤。
8. Fixture、Faux、Harness 和测试 helper 不得创建生产不存在的旁路；失败输出必须能定位到风险、边界或数据差异。

**证据**：风险—Lane 矩阵、Lane 声明、精确命令与结果、失败前后的回归证明；适用时还包括 Conformance 注册、
最终矩阵结果、未运行项及原因。

## S8 独立审查与采用

**目标失败**：实现者自证完成、Reviewer 复制同一偏见，或审查不断增加新标准使任务无法收敛。

**要求**：

1. 实现者、子 Agent 和 Reviewer 的结论均为候选；确定性门只裁定其拥有可信 Oracle 的部分。只有预先指定的
   集成者、受保护采用门或责任主体可以改变权威事实，Reviewer 的“通过”不得自动等同采用。
2. 审查至少分为两个轴：是否满足当前用户结果与合同；是否引入质量、架构、安全或维护缺陷。
3. 高风险、跨事实所有者、迁移、权限、外部副作用和治理规则变更必须由未实现该变更的主体复核。
4. Reviewer 必须区分阻断缺陷、非阻断建议和未来改进，不得在审查中静默扩大已冻结完成门。
5. Reviewer 应当读取差异和必要上下文，并独立核对关键证据；不能只复述实现者摘要。多个同模型 Agent 的一致
   意见不得按票数折算为多份独立证据。
6. 采用前由集成者确认基线未漂移、冲突已解决、验证仍覆盖最终组合结果。

**证据**：候选、验证与采用主体、独立证据通道、审查结论、缺陷定位、证据复核、建议分级和最终采用 Commit。

## S9 完成与交接

**目标失败**：用“应该完成”“测试看起来没问题”代替可接手、可复现的交付。

**要求**：

1. 交付必须先给实际结果，再列出精确变更、已运行验证、未运行项、残余风险和需要用户决定的事项。
2. 必须提供精确分支/Commit 或明确说明仍有未提交变更；不得把另一个工作树或旧 Commit 的结果当成本轮证据。
3. 未完成的工作必须保留可恢复状态和下一步，不制造假终态；外部结果未知时按目标项目的对账合同处理。
4. 升级、迁移或发布在激活前必须建立覆盖项目可控的受影响代码与数据的可定位恢复点，记录兼容与迁移影响，
   并以最终工件通过适用的消费者验证；版本号、Tag、Marker 或仅在仓库内部运行的测试不能单独证明已经激活
   或稳定。本地恢复点不等于外部状态恢复或事务补偿，外部未知结果仍须遵守 S11。
5. 除非用户授权，交付不隐含 push、PR、部署、发布、删除或清理其他工作树。
6. 跨任务或跨上下文推进必须把权威状态、阻塞原因、已决定事项、暂停/恢复点和下一动作留在耐久事实中；聊天摘要不能成为唯一恢复依据。
7. 恢复任务时必须重新确认 Git 基线、未决外部结果和适用规则版本；旧会话的完成判断不能直接继承。

**证据**：Git 状态、Commit、测试摘要、未决项、恢复入口和外部副作用记录；升级、迁移或发布还包括恢复点、
迁移影响和最终工件的消费者验证。

## S10 治理自身

**目标失败**：规则只增不减、同一变更同时降低检查标准，或把单项目经验写成永久教条。

**要求**：

1. 新规则必须记录目标失败、适用/排除条件、证据、建议机制、例外、来源和复核/删除条件。
2. 修改实现的同一变更不得静默削弱适用于它的规则、测试或检查器；确有必要时必须单独说明并由独立主体复核。
3. 一个项目的做法只能成为观察；跨项目重复出现或与目标 Workspace 约束高度匹配时，才能升级为候选或条件规则。
4. 治理资产同样受变更预算约束。重复、低触发、长期无价值或制造高误报的规则应当合并、降级或删除。
5. 用户点选的经验包默认是建议，不因作者知名、Star 数量或被点选而自动获得阻断权或额外工具权限。
6. 对重复、有限且存在可信 Oracle 的约束，应当下沉到可执行脚本、Schema 校验、测试、权限或前置检查；不能确定
   判断的设计必要性、冲突意图和例外仍由 Reviewer 或责任主体裁决。未接入受保护采用门的 Prompt 或检查结果不得
   宣称为阻断。

**证据**：规则分类、版本、来源和置信度、当前载体强度、独立复核、适用实例、例外与废弃记录。

## S11 外部动作与不可逆结果

**目标失败**：Agent 把本地实现授权扩大为外部写入，或对未知副作用自动重试。

**要求**：

1. push、PR、部署、发布、消息发送、外部数据写入和不可恢复删除必须有当前任务的明确授权。
2. 外部写入必须在执行前建立身份、权限、Scope、幂等、未知结果和对账语义；事后提示不能替代前置控制。
3. 无法确认一次调用是否成功时不得盲目重放；必须查询对账、人工处置，或明确标记未知结果。

**证据**：授权、稳定操作身份、执行回执、未知结果记录和对账结果。具体实现由目标 Workspace 的安全合同拥有。
