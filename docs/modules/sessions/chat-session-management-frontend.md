# Session 管理前端设计（第二层）

按 [前端规范](../../../.chat/interaction-harness/standards/前端规范.md) 的三步走记录：先信息与关系，再交互与展示。

## 1. 要呈现的信息

| 信息 | 来源 | 用户拿它判断什么 |
|---|---|---|
| 标题 | 用户命名，否则会话第一句话 | 这是哪条会话 |
| 时间 | 创建时间 / 最后活动 | 新旧、排序 |
| 消息数 | `messageCount` | 有没有内容、值不值得打开 |
| 归属 | 所属项目 / 所属 Long Agent | 分组与搜索范围 |
| 状态 | 运行中 / 已移除 | 现在能不能操作 |
| 命中片段 | 搜索接口 `snippet` | 这条为什么被搜出来 |

## 2. 信息之间的关系

1. **会话是主体，动作依附于会话**：重命名、移除、恢复、永久删除都作用于某一条或某几条会话。
2. **动作频率差异极大**：打开/查找是高频；重命名、移除是低频；永久删除是罕见且不可逆。
3. **危险动作需要确认与后果说明**（可恢复？保留期多久？）。
4. **批量需求真实存在**（如“清掉某月的日常会话”），但比单条操作更少见。
5. **搜索是列表的另一种视图**：结果同样是会话，只是多了“命中证据”，并支持更宽的范围与日期筛选。

## 3. 由关系推出的交互与展示

| 结论 | 依据 |
|---|---|
| 列表行默认只展示信息，不常驻动作按钮 | 动作低频，且未来还会增加（避免每加一个能力就改布局） |
| 行 hover 出现**一个 `…`**，点开 popover 菜单承载「重命名 / 移到移除区」 | 业界成熟做法（Slack 消息/频道、Notion 行）；入口稳定、可扩展 |
| 移除需要确认，文案写明“可恢复 + 保留期” | 危险动作需要后果说明 |
| 运行中的会话：菜单项禁用并说明原因 | 状态决定可执行的动作 |
| 顶部提供“选择”进入**批量操作模式**：行首勾选框 + 底部操作条 | 批量需求真实但低频（iOS 邮件 / macOS 相册 同款） |
| 移除区是同一列表的过滤视图，动作改为「恢复到项目 / 永久删除」 | 移除区不是新系统，只是同一份数据的另一种状态 |
| 搜索用**独立浮层**：输入 + 范围/日期筛选 → 结果列表（含命中片段）→ 右侧预览（命中上下文与最近消息）→ 确认后打开 | 结果可能很多，用户需要先看证据再决定打开哪一条（Raycast / Spotlight / Slack 搜索同款） |
| 搜索入口是**按钮**（不做快捷键），键盘仍支持 ↑↓ 选择、Enter 打开、Esc 关闭 | 用户明确要求按钮触发 |

## 4. 复用清单（不重复造）

| 复用对象 | 用途 |
|---|---|
| `removedSessionsPanel`（既有） | 移除区列表与恢复/永久删除动作 |
| `session-removal-browser.ts` 的 `removeSession` / `restoreRemovedSession` / `purgeRemovedSession` | 前端调用 |
| `session-list-browser.ts` 的列表读取与载荷缓存 | 打开会话复用已取到的数据 |
| 既有 `Button` / `Dialog`（`components/ui`）与 CSS 变量 | 菜单、确认框、浮层 |
| Pi 侧 `listAll` / `appendSessionInfo` | 已通过后端封装，前端不直接碰文件 |
