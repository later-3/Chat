# Chat Session 管理需求（第二层）

本文件是 [会话管理三层模型](./chat-session-architecture.md#12-会话管理能力分层2026-10-05)中**第二层**的需求与实现方案。
第二层对所有会话一视同仁：普通项目会话、Long Agent 的项目会话、每日/额外/后台工作/主题节点会话，
它们都是同一份 Pi Session 文件，只是归属与绑定不同。

## 1. 范围

**做**：查看、搜索、打开、重命名、移除（可恢复）、恢复、永久删除、保留期自动清理、批量操作。
**不做**：改变会话归属（从一个项目挪到另一个）。归属由创建入口决定，日常没有对应场景；
若将来需要“把历史会话迁移到另一个项目”，那是独立的一次性迁移。

## 2. 场景与用户交互

| # | 场景 | 用户交互 |
|---|---|---|
| 1 | 找会话 | 打开搜索（浮层）：输入关键词 + 选择筛选条件 → 结果列表（标题/时间/消息数/归属/命中片段）→ 选中条目在预览区查看最近内容 → 确认后打开 |
| 2 | 继续对话 | 点击列表行 → 右侧打开会话 |
| 3 | 重命名 | hover 行 → `…` → 重命名 → 行内输入框（预填当前标题）→ 回车保存 / Esc 取消；未改动不写盘 |
| 4 | 移除 | hover 行 → `…` → 移到移除区 → 确认（说明可恢复与保留期）→ 行消失；运行中的会话该项禁用 |
| 5 | 恢复 | 移除区 → `…` → 恢复到项目 → 回到活动列表，绑定自动生效 |
| 6 | 永久删除 | 移除区 → `…` → 永久删除 → 不可恢复确认 |
| 7 | 批量 | 进入**批量操作模式**：行首出现勾选框、底部出现操作条 → 移到移除区（移除区为恢复到项目 / 永久删除） |
| 8 | 查看已移除 | 列表附近入口「已移除 (N)」→ 切换移除区视图（顶部说明保留期） |

**搜索与浏览的筛选条件（都可选，不是二选一）**：范围＝当前项目 / 该 Long Agent 的全部项目 / 全部会话（移除区也可作为范围）；时间＝创建日期区间（今天 / 近 7 天 / 自定义）；关键词＝标题＋第一句话＋全文。

## 3. 能力来源与实现路径

| 能力 | Pi 生态 | Chat 现状 | 实现路径 |
|---|---|---|---|
| 列举（标题/首句/全文/时间/消息数） | SDK `SessionInfo` 提供（含 `allMessagesText`） | 已用，但未传全文 | 复用，搜索时补全文 |
| 全文搜索 | Pi TUI 已实现（`id + name + allMessagesText + cwd`） | 只搜标题+首句 | **补齐**：后端按 `query` 匹配全文后返回命中会话 |
| 打开 | `SessionManager.open` | 已有 | 复用 |
| 重命名 | `appendSessionInfo` | 已有（含 LA 归属解析） | 复用 |
| 移除 | **SDK 无删除 API**；Pi TUI 用系统 `trash`，Pi Web 真删 | Chat 自有移除区（软删） | **复用 Chat 实现**，补 LA 归属定位 |
| 恢复 / 永久删除 / 保留期 | 无 | Chat 自有，已实现 | 复用；让 LA 视图可用 |
| 批量 | 无 | 无 | 前端多选 + 复用同一移除接口 |
| fork | SDK/TUI/Pi Web 均有 | 普通会话可用；LA 上下文前端隐藏入口 | 属创建机制，是否放开由产品决定 |

## 4. 前端交互设计

```text
浏览态（默认）：行默认干净 —— 标题 · 时间 · 消息数 · [类型标记]
  点行打开；hover 行尾出现一个 “…”：重命名 / 移到移除区
批量操作模式（顶部“选择”）：行首勾选框 + 底部操作条
移除区（按项目天然存放的同一列表过滤视图，范围同样可切换）：行尾 “…”：恢复到项目 / 永久删除；顶部保留期说明
搜索：独立浮层（输入 → 结果列表 → 预览 → 确认打开）
```

约定：低频、危险、需要批量的动作不常驻在行上；行上只保留一个 `…`，未来新增动作不改布局。

## 5. 后端实现

1. **统一会话定位**（关键改动）：抽出共享函数 `resolveOwnedSessionProject(projectId, sessionId, chatHome)`
   ——先在共享项目目录查找；未命中且有 `projectSessions` 绑定时用 `{ownerLongAgentId}` 解析到 Agent 项目树。
   重命名、移除、恢复、永久删除全部走它。
2. **移除链 owner 化**：`src/session-removal.ts` 四处 `resolveProjectContext(projectId, chatHome)` 改用统一解析；
   移除区列表接口新增可选 `owner` 查询参数。
3. **附属数据**：会话记忆走 owner 参数；prompt captures 位于 `sessionDir` 下随解析正确；
   主题节点生命周期仅在 Agent Home 触发（现状合理）。
4. **搜索**：`GET /api/sessions?scope=project|agent|all&projectId=…&query=…&createdFrom=…&createdTo=…&includeRemoved=…`；
   匹配标题、第一句话与 `allMessagesText`；`scope` 决定遍历哪个存储根，`includeRemoved` 决定是否包含移除区。
5. **绑定索引**：移除后绑定记录保留（用于恢复识别），列表侧已跳过缺失文件，无需新增逻辑。
