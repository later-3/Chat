# Long Agent 每日工作与归档

状态：2026-09-30 已实现并完成隔离验证，尚未部署。此合同替代旧的“在昨天私聊 Session 内运行日终整理”。

## 业务场景与机制选择

用户要管理 Agent 一整天的事项，而非只压缩一次聊天。每日总结属于 Agent 的每日工作和连续性记忆，不属于用户对话，也不是 Workflow 的 session-memory-writer 节点。日期按 Agent / Task 的 IANA 时区确定。

采用既有 Task → Occurrence → 独立 Work Session → Workflow → 公共 Pi 装配链；NanoClaw 继续独占时钟计算和触发。Chat 的维护循环只恢复队列、同步任务，不直接调用模型总结。不新增运行时或调度器（机制合同 E2/E3）。

## 技术方案与边界

1. 为每个启用的 Agent 幂等创建一项有类型标记的每日总结任务。默认次日 00:10 总结前一天，missed=latest、overlap=queue-one。可在既有任务管理中调整、暂停、取消；取消后不自动重建。不按名称猜测或删除用户已有任务。
2. 发生记录冻结覆盖日期，迟到执行仍总结原日期。手动补写允许指定过去日期；执行和写入均保留 Work / Occurrence 来源。任务的模型终态与总结文件是否落盘分开显示，回答“完成了”不能替代文件。
3. 由 Backend 投影当日原生 Session、任务发生记录、独立工作与职责关联（含跨日进行中工作）；Agent 用同源 `summary_manage` 查询日目录、按 Session ID 分页读取自己的历史，不能用路径或 Agent ID 扩大权限。群参与沿用原授权检查，撤销后不重新开放历史；群独立工作的私密执行正文仍遵守原有 owner-only 合同，目录仅提供任务元数据。含群来源的总结在 Agent 加载前重新检查参与权限。
4. 每日目录 `long-agents/<id>/days/<YYYY-MM-DD>/` 保存独立 `summary.md` 及写入时的来源索引。原生 Session、Task、Work 保留原存储归属，日目录用稳定引用关联，不移动、不复制另一套执行事实。旧 summaries 继续兼容读取。
5. 公共 Long Agent 装配说明每日工作机制，默认只注入昨天的总结；更早日期通过 Tool 检索。无总结明确标记缺失，不把几天前的总结冒充昨天。群聊仍排除私密交接。
6. 普通聊天投影隐藏旧日终维护输出，原生历史保留供审计。任务与归档界面展示日总结文件、实际执行和错误；历史日期支持跨年，读取失败不得显示为空档案。
7. 聊天工具栏区分常用操作与低频设置，统一现有 ToolbarAction、Tabler 图标、按钮尺寸、提示和键盘操作；不新增第二套 UI 组件。
8. 默认 Agent 配置已包含 `summary_manage`。用户裁剪过工具配置时，不自动扩大权限；没有该工具的总结任务显示阻塞原因，检查授权后再执行。总结缺失、损坏或来源不可读时，新会话照常受理并明确交接不可用。

## 验证要求

隔离 Chat Home、假模型、独立构建目录验证：幂等任务、暂停/取消、跨时区及迟到触发、当日多类事项、历史权限与分页、独立 Markdown、次日交接、旧聊天隐藏、前端响应校验、失败状态与宽窄屏。修改公共装配需验证 Builder / 开发 bundle / 生产构建 / test:dev。不得构建覆盖正在运行的生产目录或修改正式资料。

2026-09-30 验证结果：

- Backend 685 项、Frontend 269 项、工具链 58 项、生产 HTTP 30 项通过；类型检查、前后端与 CLI 构建通过。Builder 转换、开发 Step bundle 装载和真实 Workflow / Pi Runtime 均已覆盖。
- `pnpm verify` 在隔离源码副本执行，开发链 9 项通过、2 项浏览器用例失败、1 项付费模型用例显式跳过。失败来自旧测试直接寻找已进入手机菜单的按钮，以及在同一天多 Session 中默认点击第一项。修正为明确桌面视口、手机菜单键盘操作、按 Session ID 选择后，两条分别复测通过（约 13 秒、30 秒）；不将首次非零退出记成一次全绿。
- 最终界面调整后重新执行 Frontend 269 项、类型检查、完整构建及生产 HTTP 30 项，均通过；浏览器回归覆盖 390/768/1440px、首次完整历史、开关持久化、跨日期导航和刷新恢复。人工检查中英文、归档正文及来源、手机记忆菜单；手机实测 CSS 视口 391px，输入区宽 324px，顶部动作不重叠。
- 隔离生产服务通过真实任务 API → 独立 Work → Workflow → Pi Tool 保存 Markdown；原私聊不新增总结消息。全部执行使用临时 Chat Home / 本地假模型，未修改正式 Session，未发布，未触达外部渠道。真实模型的总结内容质量及部署后的日终运行仍需实际验收。
- 证据位于 Git 忽略的 `.data/verification/daily-archive-2026-09-30/`；`git diff --check` 与 Frontend 同项检查通过。业务复盘与 experience 资源见 [历史消息归属与加载就绪](../../development/experiences/session-history-provenance-and-readiness.md)。
