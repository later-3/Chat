## 6. Muse Spark 1.3C 为什么感觉慢（实测结论）

你的体感是对的，实测确认：

1. **不是生成慢，是思考太多**。142.6 tok/s 在标准池排第二快；但对一个简单的编码问题，700 个输出 token 里 697 个是思考（99.6%），而且 700 上限都没想完（✂️），真实耗时 >9.5s。
2. **首 token 慢**。TTFB 4.56s，标准池倒数第二，只比满血 GLM-5.3（6.05s）快——思考全发生在出第一个字之前。
3. **对照**：同一问题，Sonnet 5.5 3.3s 跑完、DeepSeek V4.1 Flash 4.2s 跑完、Haiku 2.4s 跑完。Muse 1.3C 是它们的两倍以上。
4. 同样的"思考大户"还有 GLM-5.3 Flash（100% 思考、3.57s TTFB）和满血 GLM-5.3——这俩也不适合当速度型模型。

**使用建议**：
- 默认保留 Muse 1.3C 没问题（性价比断层第一），适合质量优先、不赶时间的轮次；Command 侧思考无法关闭，只能用 `reasoning_effort: low` 试着压缩（效果待实测）。
- 速度敏感场景切这三档：**claude-sonnet-5-5**（3.3s、56 分，旗舰池质量速度双优）、**deepseek-v4.1-flash**（4.2s、184.8 tok/s，标准池最均衡）、**claude-haiku-5-5**（2.4s、285.5 tok/s，纯快）。
- Chat 工作流里对时延敏感的节点（如状态轮询、轻量总结）建议指定 DeepSeek V4.1 Flash 而不是默认 Muse。
