# 当执行到export function createRuntimeApiClient(options: RuntimeApiClientOptions) {这里的时候，就意味着我们走到了后端？

createRuntimeApiClient 不是后端代码,执行到这里时你在 Workflow Runtime 进程里,它是 Workflow 调用后端的客户端 。

```
┌─────────────────────────────────────────────────────────────┐
│ 浏览器 (apps/web, React)                                     │
│   用户输入"你好" → POST /api/sessions/:id/messages           │
└──────────────────────────┬──────────────────────────────────┘
                           ↓ HTTP
┌──────────────────────────┴──────────────────────────────────┐
│ 后端 API (apps/api, Hono, port 43110/43111)                  │
│   ① 存消息"你好"到 Product Store                              │
│   ② 创建 Product Run + Run Attempt                           │
│   ③ 写 Outbox 派发任务                                        │
│   ④ Outbox dispatcher 推给 Workflow Runtime                  │
└──────────────────────────┬──────────────────────────────────┘
                           ↓ 内部派发
┌──────────────────────────┴──────────────────────────────────┐
│ Workflow Runtime (packages/workflows, port 43112)  ← 你在这里 │
│   执行 planningExecutionWorkflow                             │
│   step 里调 ctx.api.beginPlanningContext(...)                │
│   ↓                                                          │
│   createRuntimeApiClient 的方法发 HTTP 回后端                 │
└──────────────────────────┬──────────────────────────────────┘
                           ↓ HTTP (port 43111 internal)
┌──────────────────────────┴──────────────────────────────────┐
│ 后端 API (apps/api, 同一个进程, internal router)              │
│   处理 /internal/runtime/v1/begin-planning-context           │
│   查 Product Store,返回上下文                                 │
└─────────────────────────────────────────────────────────────┘
```

### "前端的数据在哪儿?"
前端的数据(用户发的"你好") 在后端的 Product Store 里 ,不在 Workflow Runtime 里。

数据流:

1. 前端发"你好" → 后端存到 Product Store 的 messages 表
2. 后端创建 Run,派发给 Workflow Runtime
3. Workflow Runtime 只拿到 productRunId + attemptId (引用,不是原文)
4. Workflow 通过 beginPlanningContext(productRunId) 回后端查 → 后端用 productRunId 去 Product Store 读"你好"和上下文 → 返回给 Workflow
Workflow Runtime 从头到尾不持有"你好"原文 ,只持有 productRunId 引用。需要时回后端查。这就是 planning-execution-workflow.ts L97-99 注释说的:

 productRunId 是 Chat 产品身份;attemptId 是 Chat 的 Workflow Attempt 证据。二者都不是 Vercel Workflow Run ID,Step 只能借它们调用内部 Application API。

## 一句话记忆

|代码位置| 在哪个进程 角色 
apps/web 浏览器 前端(用户交互) 
apps/api 后端进程 (43110/43111) 服务端(持有 Product Store 权威事实) 
packages/workflows Workflow Runtime 进程 (43112) 工作流执行器(通过 api-client 回调后端)

api-client.ts 里的 createRuntimeApiClient = Workflow Runtime 的 HTTP 客户端 ,用来回调后端读写产品事实。前端数据永远在后端 Product Store,Workflow 只拿引用去查。
