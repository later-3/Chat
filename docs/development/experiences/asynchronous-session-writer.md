# 异步返回必须释放旧 SessionManager

## 现象与根因

LA0 接缝验证复现：子 Workflow 等待期间父聊已追加新消息，旧父 SessionManager 再 append 会从自己的旧 leaf 延伸。JSONL 仍有新消息，但当前分支不再包含它；“原文件没丢行”不足以证明会话正确。

## 为什么原有验证没有发现

仅验证子结果内容和最终状态，没有让另一写入者在等待窗口后打开父 Session 并继续交流，也没重开文件检查当前 branch。只在 append 外加锁仍可能把旧 manager 搬进锁内，不能解决旧 leaf。

## 实现与验证

等待窗口内允许当前持锁者同步写自己的 manager；窗口结束立即释放这项权利。迟到回调只携带稳定标识，取得同一 Session 操作锁后重新打开文件、核对归属并幂等提交。来源已删除不重新创建；跨日 Friend 工作结果留在工作入口，不隐式唤醒或改写旧日。原生结果及耐久执行状态先保存，返回通知失败可以再消费，不能再次调用模型。

回归：`test/long-agents/background-work.test.mjs` 使用实际 Workflow 写入器，先持锁追加新用户消息，再释放并重复返回，断言重开后的当前分支保留新输入且返回标记仅一条；同时覆盖主聊与工作并发、跨日、取消及重启不明执行不重放。LA0 原型只用于复现，不代替生产代码门禁。
