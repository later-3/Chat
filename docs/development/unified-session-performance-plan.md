# 统一 Session 执行与导航性能

状态：实现、功能验收与最终构建性能采样完成。工作分支 `codex/unified-session-performance`；隔离构建，不覆盖运行中的 43110。

## 已确认场景与边界

Long Agent 日常会话、主题节点会话和 Project 会话均为 Pi Session。用户可在同一会话选择 Workflow，读取历史、发送、图片、流式工具过程、审核、追加、停止、恢复和记忆使用公共能力。Friend 身份、渠道来源、每日归属、主题父边和协作 Project 是可信业务上下文，不是另一套 Agent 运行时。

公共装配与 Pi Session 是唯一执行基础。接受队列负责请求身份、冻结授权和顺序；Workflow Runtime 负责 Run/Step。普通聊天仍是最小 Workflow，不强制额外规划。既有记录保留可读，结果不明的工具执行不自动重放。不能用统一 API 外壳宣称执行已经统一。

## 实施与退出检查

1. 统一执行：可信执行绑定、默认与规划审核 Workflow、Run/接受记录关联、公共阶段装配和控制反馈。先证明 Friend 原会话默认聊天→规划审核→继续聊天，再覆盖主题/Project/Channel/后台工作。提交窗口中断不得重复启动或丢失已受理请求。
2. 导航性能：复用 Pi 派生列表信息，以文件身份/版本失效；去除周期性全历史解析；会话打开先提供聊天首屏，树/历史按需；近期视图立即展示并后台校准；切换取消读取/观察，不取消执行。
3. 联合验证：三类会话功能矩阵，原有全门禁（Builder、Nitro dev、生产 Runtime），真实数据规模实验和真实浏览器切换。性能目标暖切换 p95 ≤100ms，选择反馈/输入可用 p95 ≤50ms；分别报告冷打开、暖切换、后台活动、请求/字节和数据规模，不以小夹具结果代替真实数据。
