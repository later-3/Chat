# Pi 会话维护入口实施

状态：已实施，Chat 完整验收通过（1003 项），Pi 26 项定向回归通过；Pi 全仓 check 的 11 处既有模型目录类型错误另列记录。2026-09-27 用户授权先补压缩失败、取消、恢复与预算准入，再接通维护入口。具体合同以 [原生会话维护](../modules/sessions/chat-session-maintenance.md) 为准，结果见 [验收记录](../history/reviews/2026-09-27-pi-session-controls.md)。未提交、未部署。

## 场景与边界

1. 所有普通对话、压缩、分支摘要及摘要重试均通过 Pi SDK 共用模型流的 payload 准入。门禁拒绝不能发 HTTP；截断/失败/取消不能写入成功摘要。
2. 用户在空闲会话主动压缩：Backend 复用公共装配与 Pi `compact()`，不发送伪造用户消息、不另写摘要算法、不运行第二套 Agent Loop。采用 Session 操作锁，原生 JSONL 保存操作关联和结果，浏览器离开只停止观察，显式取消调用 `abortCompaction()`。进程中断不自动重放收费请求。
3. 统计是 Pi 全文件只读聚合，包含旧分支、压缩与工具用量；上下文占用是当前分支估计，压缩后尚无新响应时未知。为此把 Pi 原有统计函数提取为公共只读 API，AgentSession 继续调用相同函数；Chat 不加载扩展、不启动模型。
4. 历史浏览保持只读。显式“从这里继续”需要服务端 expectedLeafId 冲突检测，复用 Pi 原生分支，追加纯元数据使选中叶在重开后仍有效。原始消息及旧分支不变。仅允许完整对话边界，不能从未完成工具调用中间继续；不会自动重放工具。

## 归属与并发

Project/Session 由 Backend 精确解析；写前验证 owner、可写性和 Workflow/Friend 队列。群公开/参与/工作记录不能通过通用入口绕开群预算和发布合同，必须检查原生绑定，不能只看导航 roster。主题分支沿用主题节点的专有分叉合同，不让普通树导航破坏锚点。

维护生命周期只适配 Pi 原生操作，不能接管 Workflow 对話执行、权限或状态。请求携带稳定 requestId，相同请求重读已有结果，冲突请求拒绝；恢复只认原生落盘事实。运行中的会话明确返回忙碌，不隐式取消现有工作或排队收费维护。

## 验证

原生 SDK 回归 + 公共装配本地 HTTP + Nitro 实际 Workflow/Step + 浏览器入口。检查取消状态、摘要重试事件、预算拒绝零 HTTP、半份摘要不落盘、重启无重放、同 ID 恢复、叶冲突、跨归属拒绝及中英文。最终执行 Pi `npm run check`、Chat `pnpm verify` 与差异检查。
