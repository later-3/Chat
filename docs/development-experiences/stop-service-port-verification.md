# 停机检查遗漏监听地址

## 现象与根因

2026-09-08实现统一关闭入口时，只读检查发现NanoClaw的3000端口被报告为空闲，但`lsof`显示Host仍监听`*:3000`。原探测只尝试绑定`127.0.0.1`；改为只探测`0.0.0.0`后，又漏报了监听`127.0.0.1:43110`的Backend。macOS允许特定条件下通配与回环绑定并存，因此一个地址上的bind成功不足以证明端口空闲。此前测试只创建回环监听器，未覆盖Nano的实际监听形式。

## 修复与验证

`assertPortFree()`依次检查IPv4/IPv6的回环与通配地址；仅IPv6明确不支持/地址不可用时跳过，其余错误视为检查失败。关闭结果同时核对原生服务管理状态、原PID身份与端口，不用端口代替进程归属。此检查仍是时点检查，之后被另一个进程重新绑定时应再次检查，不能宣称永久锁定端口。

- `scripts/debug-environment.test.mjs`以真实回环及通配监听器验证占用被拒绝、原监听器继续存活。
- `scripts/chat-stop.test.mjs`验证残留端口/原PID阻止假成功；真实macOS临时KeepAlive服务经bootout后停止且可重复关闭，普通dev脚本及子进程退出而无关监听器保留。
- 正常服务只读检查与停止测试分离；不对用户生产服务执行试停。

对应`stop-service-port-verification` experience通过既有Personal Prompt资源初始化机制发布，仍需显式选择才装配给Agent。
