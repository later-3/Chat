# 朋友圈被侧栏约束与缺失翻译

## 现象与根因

朋友圈入口打开后，内容追加在联系人列表底部，标题和空状态显示 `longAgentSettings.socialHeading` 等内部键。`LongAgentFeedView` 复用了设置页 CSS，并作为普通 section 参与侧栏 flex 布局；两个语言包均未注册这些键。空数据时没有帖子可暴露更多布局问题。

## 原验证缺口

已有 TypeScript 类型允许任意翻译 key，语言包也使用 string 索引。编译通过不能发现缺失翻译；合同测试无法证明模态内容逃离侧栏尺寸约束。原 feed 还只断言 posts 为数组，非法时间或评论可进入视图。

## 修复与可复用结论

独立朋友圈由全局导航进入 AppShell 主内容区，移除同事列表按钮和弹窗。聊天保持挂载，测试返回后的草稿、滚动和连接，并停用隐藏聊天的全局快捷键。文案测试遍历触达组件引用的所有键，并检查中英文均已注册。网络边界验证帖子、评论、时间与重复 ID，将非法结果显示为可重试错误。使用隔离 API fixture 检查有内容、空内容、筛选为空和失败状态，截图中的演示内容不写入用户数据。

## 回归门禁

`frontend/lib/long-agent-feed.test.mjs` 覆盖双语键、动态与评论解析、失败语义及全局页面与移动布局约束。浏览器验收覆盖 360/390/768/900/1024/1440 宽度下的深浅主题，历史返回/焦点恢复及隐藏聊天不响应 Escape，评论展开、作者筛选、重试、长文本与 200% 缩放。当前开发服务与正式服务共享 checkout 时，构建验证在独立目录执行，不能覆盖正式构建产物。

对应 Experience：`social-feed-surface-and-translations`，仅作为可选择的 Personal Prompt 资源，不自动加入任何 Agent 默认能力。
