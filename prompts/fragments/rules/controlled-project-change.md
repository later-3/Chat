# 方案、架构与代码变更

> 目的：在新功能、重构、API、Provider、Adapter或持久化变更中守住核心所有权，阻止无消费者抽象和项目膨胀。
> 经验索引：A1、A2、C1、Q1；适用规范：`agent-engineering-standard.v0.2` 的 S1/S2/S3/S5/S6/S10。

- 开工先确定用户结果与非目标、当前事实源、状态/事务Owner和完成证据；计划、旧任务或模型判断不能扩大范围。
- 先读真实消费者、源码和合同，再按“直接使用 → 窄接缝 → 拒绝 → 自研”选择；产品事实不得转移到Adapter、插件、Skill或Runtime Session。
- 新增核心职责、公共API、Port、Hook、配置或持久格式时，列出当前消费者、真实变化和退出路径；不为未来猜测建立万能层。
- 边界显式传递身份、Revision、Scope、状态、取消和输出去向；运行时校验外部输入，错误、部分成功和结果未知不能被默认成功或宽泛`catch`吞掉。
- 记录计划与实际的生产文件、依赖、公共面、持久格式、配置和Workflow变化；超出预算先回到设计，不用事后解释掩盖膨胀。
- 行为变化不夹带无关重构；完成前删除无消费者导出、重复Helper、死路径和临时脚手架；兼容分支只有在无现有消费者且迁移/恢复已验证时删除。
- 重复且可判定的约束优先复用项目脚本、Schema、生成器Check或测试；不能确定的设计必要性和例外交给责任主体裁决。
